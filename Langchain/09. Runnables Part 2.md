## Introduction

In this lesson, we explore how LangChain's Runnable system helps us connect individual components into flexible AI workflows. We will learn how to execute components sequentially, run multiple operations in parallel, preserve intermediate results, introduce custom Python logic, and route inputs conditionally.

The central idea is simple:

> Individual components perform tasks, while Runnable primitives help coordinate those tasks into complete workflows.

These notes include conceptual explanations, flow diagrams, Python code examples, practical use cases, and a comparison of the different primitives.

---

## 1. Recap: The Runnable Interface

In the earlier lesson, LangChain's core components were introduced as reusable building blocks for AI applications.

Examples include:

- **Prompt templates** – help design prompts.
- **Language models (LLMs)** – generate responses.
- **Output parsers** – process model outputs.
- **Retrievers** – retrieve relevant documents.

Originally, these components exposed different methods for interacting with them. For example, a prompt might use `format()`, a model might use `predict()`, a parser might use `parse()`, and a retriever might use `get_relevant_documents()`.

This made it harder to connect components into flexible workflows.

### The Runnable abstraction

LangChain introduced a standardized interface called a **Runnable**. The key method is:

```python
result = runnable.invoke(input_data)
```

With a common interface, the output of one component can be passed to the next component in a pipeline.

### The basic Runnable workflow

```text
Input
  |
  v
Prompt Template -- formats input
  |
  v
LLM -- generates output
  |
  v
Output Parser -- processes output
  |
  v
Result
```

Each component can participate in a pipeline through the standardized Runnable interface.

## 2. Types of Runnables

The lesson divides Runnables into two categories.

| Category | Purpose | Examples |
|---|---|---|
| Task-specific Runnables | Perform a particular task | Prompt templates, chat models, retrievers, parsers |
| Runnable primitives | Coordinate execution and connect other Runnables | `RunnableSequence`, `RunnableParallel`, `RunnablePassthrough`, `RunnableLambda`, `RunnableBranch` |

### 2.1 Task-specific Runnables

These are the components that perform the actual work in an AI application. They have a defined purpose, such as generating text, formatting a prompt, retrieving documents, or parsing a response.

### 2.2 Runnable primitives

Runnable primitives are the building blocks used to organize execution logic. They help determine:

- Whether operations execute sequentially or in parallel.
- Whether an input should be passed through unchanged.
- Where custom Python logic should run.
- Which processing path should be selected conditionally.

The following sections explain the primitives covered in the lesson.

## 3. RunnableSequence

**Sequential execution**

### What is RunnableSequence?

`RunnableSequence` is a Runnable primitive that connects two or more Runnables in a sequence.

The output of the first Runnable becomes the input of the next Runnable. This continues until the final Runnable produces the result.

For example, consider two Runnables:

- `R1`: A prompt template.
- `R2`: A language model.

When connected sequentially, the prompt is formatted first and the resulting prompt is passed to the model.

### 3.1 Example: Generate a joke

The following example creates a chain that generates a joke about a user-provided topic.

```python
from langchain_openai import ChatOpenAI
from langchain_core.prompts import PromptTemplate
from langchain_core.output_parsers import StrOutputParser
from langchain_core.runnables import RunnableSequence
from dotenv import load_dotenv

load_dotenv()

prompt = PromptTemplate(
    template="Write a joke about {topic}",
    input_variables=["topic"]
)

model = ChatOpenAI()
parser = StrOutputParser()

chain = RunnableSequence(prompt, model, parser)

result = chain.invoke({"topic": "AI"})
print(result)
```

**How it works:**

1. The input dictionary supplies the topic.
2. The prompt template formats the instruction.
3. The model generates a joke.
4. The parser returns the output as a string.

### 3.2 Example: Generate a joke and explain it

We can extend the previous chain by adding another prompt, model call, and parser.

```python
prompt1 = PromptTemplate(
    template="Write a joke about {topic}",
    input_variables=["topic"]
)

prompt2 = PromptTemplate(
    template="Explain the following joke:\n{text}",
    input_variables=["text"]
)

joke_chain = RunnableSequence(prompt1, model, parser)

explanation_chain = RunnableSequence(
    prompt2, model, parser
)

final_chain = RunnableSequence(
    joke_chain, explanation_chain
)

result = final_chain.invoke({"topic": "AI"})
print(result)
```

The first chain generates the joke. The second chain receives that joke and generates its explanation.

## 4. RunnableParallel

**Parallel execution**

### What is RunnableParallel?

`RunnableParallel` executes multiple Runnables using the same input. Each Runnable processes that input independently, and the results are collected into a dictionary.

This is useful when multiple tasks do not depend on one another.

For example, given the topic `"AI"`:

- One chain generates a tweet.
- Another chain generates a LinkedIn post.

Both chains receive the same topic, and their outputs are collected separately.

## 5. RunnablePassthrough

**Preserving and forwarding input**

### What is RunnablePassthrough?

`RunnablePassthrough` is a Runnable primitive that forwards the input it receives **without changing it**. Its output is the same value as its input.

This behavior may seem simple, but it becomes useful when a chain needs to do additional processing while also retaining the original data. Without a passthrough path, a sequential workflow generally returns the output of its final step, which may replace or obscure an earlier value.

### 5.1 Basic behavior

Suppose we pass a string into `RunnablePassthrough`. It returns that same string unchanged:

```python
from langchain_core.runnables import RunnablePassthrough

passthrough = RunnablePassthrough()

result = passthrough.invoke("Why did the model cross the road?")

print(result)
# Why did the model cross the road?
```

No transformation is applied to the input.

### 5.2 Why is it useful?

Consider a workflow that generates a joke and then sends it to another model to explain the humor. A `RunnableSequence` that connects joke generation to joke explanation returns the explanation as its final result. If the application also needs the original joke, it must preserve that value before or while the explanation is generated.

`RunnablePassthrough` can act as one branch of a `RunnableParallel` operation. One branch forwards the original joke, while another branch performs a separate task. The parallel operation then collects both results in a dictionary.

### 5.3 Execution flow: preserve a joke and produce another result

```text
                 Input: generated joke
                           |
                +----------+----------+
                |                     |
                v                     v
      RunnablePassthrough       Processing Runnable
         keeps the joke          works on the joke
                |                     |
                v                     v
           Original joke          New result
                |                     |
                +----------+----------+
                           |
                           v
                  Combined dictionary
```

For example, the resulting dictionary could have one key for the original joke and another for its explanation or word count. The exact keys depend on how `RunnableParallel` is configured.

### 5.4 Example: preserve the input while counting words

This example demonstrates the passthrough branch alongside a custom word-count Runnable:

```python
from langchain_core.runnables import (
    RunnableParallel,
    RunnablePassthrough,
    RunnableLambda
)

word_count = RunnableLambda(
    lambda text: len(text.split())
)

parallel_chain = RunnableParallel({
    "text": RunnablePassthrough(),
    "word_count": word_count
})

result = parallel_chain.invoke("LangChain makes AI development easier")

print(result)
# {
#     "text": "LangChain makes AI development easier",
#     "word_count": 5
# }
```

The `text` branch preserves the input, while the `word_count` branch calculates a value from it. `RunnableParallel` combines their outputs into a dictionary.

### When to use RunnablePassthrough

Use `RunnablePassthrough` when you need to:

- Keep an original input available while other processing occurs.
- Return the input alongside derived values.
- Create a branch in a parallel workflow that simply forwards its input.
- Avoid adding an unnecessary transformation when the value should remain unchanged.

**Key takeaway:** `RunnablePassthrough` does not perform the additional processing itself. It preserves the value so the surrounding workflow can use it together with results from other Runnables.

## 6. RunnableLambda

**Custom Python logic**

### What is RunnableLambda?

`RunnableLambda` converts a regular Python function into a Runnable.

This allows us to insert custom Python logic into a LangChain pipeline and connect it with other Runnables.

For example, suppose we are analyzing customer reviews. Before sending a review to an LLM, we may want to preprocess the text by:

- Converting text to lowercase.
- Removing unwanted punctuation.
- Cleaning HTML tags.
- Applying other custom transformations.

Instead of keeping this logic outside the chain, we can wrap the function with `RunnableLambda`.

### 6.1 A simple word-count function

First, define an ordinary Python function.

```python
def word_counter(text):
    return len(text.split())

print(word_counter("LangChain makes AI development easier"))
# 5
```

This function counts the whitespace-separated tokens in the string. It is a simple demonstration rather than a full linguistic word-count algorithm.

### 6.2 Convert the function into a Runnable

```python
from langchain_core.runnables import RunnableLambda

runnable_word_counter = RunnableLambda(word_counter)

result = runnable_word_counter.invoke(
    "LangChain makes AI development easier"
)

print(result)
# 5
```

Now the function can be composed with other Runnables.

### 6.3 Using a lambda expression directly

A short Python lambda can also be wrapped:

```python
word_counter = RunnableLambda(
    lambda text: len(text.split())
)

print(word_counter.invoke("Hello from LangChain"))
# 3
```

Both approaches allow custom Python code to participate in a Runnable workflow.

### 6.4 Example: Generate a joke and count its words

We can combine the previous concepts:

1. Generate a joke using a prompt and model.
2. Parse the model response into a string.
3. Run two parallel operations:
   - Pass the joke through unchanged.
   - Count the words in the joke.
4. Return both results.

<img width="717" height="290" alt="image" src="https://github.com/user-attachments/assets/55b69ec7-1da7-4f90-80c3-3afd76b6b8c7" />


```python
from langchain_core.runnables import (
    RunnableSequence,
    RunnableParallel,
    RunnablePassthrough,
    RunnableLambda
)

joke_chain = RunnableSequence(
    prompt, model, parser
)

word_count = RunnableLambda(
    lambda text: len(text.split())
)

parallel_chain = RunnableParallel({
    "joke": RunnablePassthrough(),
    "word_count": word_count
})

final_chain = RunnableSequence(
    joke_chain, parallel_chain
)

result = final_chain.invoke({"topic": "AI"})

print(result["joke"])
print(result["word_count"])
```

The output dictionary contains the original joke and its calculated word count.

## 7. RunnableBranch

**Conditional execution**

### What is RunnableBranch?

`RunnableBranch` is a primitive for creating conditional workflows. It behaves conceptually like an `if/else` statement.

It evaluates conditions in order and executes the Runnable associated with the first condition that evaluates to `True`. If no condition matches, it executes the default Runnable.

### 7.1 Example: Route customer emails

Imagine a customer-support system receiving emails that can be categorized as:

- Complaints.
- Refund requests.
- General queries.

Each category may require a different action:

| Email category | Intended handling |
|---|---|
| Complaint | Forward to customer support |
| Refund request | Trigger the refund-handling workflow |
| General query | Generate a chatbot response |

A workflow could first classify the email and then use `RunnableBranch` to select the appropriate processing chain.

### 7.2 Example: Summarize long reports

The lesson demonstrates another conditional workflow:

- Generate a report about a topic.
- Count the words in the report.
- If the report exceeds a word-count threshold, summarize it.
- Otherwise, return the original report unchanged.

<img width="709" height="358" alt="image" src="https://github.com/user-attachments/assets/a39d2961-baa7-4666-9835-c0908ed8da5c" />


### 7.3 RunnableBranch syntax

A branch is constructed using condition-and-Runnable pairs, followed by a default Runnable.

```python
from langchain_core.runnables import (
    RunnableBranch,
    RunnableLambda,
    RunnablePassthrough
)

branch = RunnableBranch(
    (
        lambda text: len(text.split()) > 500,
        summary_chain
    ),
    RunnablePassthrough()
)
```

In this example:

- The first tuple contains a condition and the Runnable to execute when that condition is true.
- `RunnablePassthrough()` is the default branch when the report does not exceed the threshold.

### 7.4 Complete report workflow

```python
report_prompt = PromptTemplate(
    template="Write a detailed report on {topic}",
    input_variables=["topic"]
)

summary_prompt = PromptTemplate(
    template="Summarize the following text:\n{text}",
    input_variables=["text"]
)

report_chain = RunnableSequence(
    report_prompt, model, parser
)

summary_chain = RunnableSequence(
    RunnableLambda(lambda report: {"text": report}),
    summary_prompt,
    model,
    parser
)

branch_chain = RunnableBranch(
    (
        lambda report: len(report.split()) > 500,
        summary_chain
    ),
    RunnablePassthrough()
)

final_chain = RunnableSequence(
    report_chain,
    branch_chain
)

result = final_chain.invoke({"topic": "AI"})
print(result)
```

The threshold can be changed to suit the application. The lesson also demonstrates lowering the threshold to make the summarization branch easier to trigger during testing.

## 8. LangChain Expression Language (LCEL)

### What is LCEL?

LCEL stands for **LangChain Expression Language**.

The lesson introduces LCEL as a declarative way to define Runnable sequences using the pipe operator (`|`).

Instead of explicitly constructing a `RunnableSequence`, we can write:

```python
chain = prompt | model | parser
```

This expresses the same sequential composition as:

```python
chain = RunnableSequence(
    prompt, model, parser
)
```

### Two ways to define a sequence

**Explicit composition**

```python
chain = RunnableSequence(
    prompt, model, parser
)
```

**LCEL pipe syntax**

```python
chain = prompt | model | parser
```

Both forms compose the prompt, model, and parser sequentially.

### 8.1 Why use the pipe operator?

The pipe syntax makes sequential chains concise and readable. It clearly communicates the order in which components are composed.

For example:

```python
joke_chain = prompt | model | parser

result = joke_chain.invoke({"topic": "AI"})
print(result)
```

The prompt's output is passed to the model, and the model's output is passed to the parser.

### 8.2 LCEL and Runnable primitives

The lesson emphasizes that sequential composition is a common operation. LCEL's pipe syntax provides a convenient way to express it.

Other primitives still serve their own purposes:

| Primitive | Main responsibility |
|---|---|
| `RunnableSequence` | Compose Runnables sequentially |
| `RunnableParallel` | Execute independent Runnables using the same input |
| `RunnablePassthrough` | Pass input through unchanged |
| `RunnableLambda` | Wrap custom Python logic |
| `RunnableBranch` | Select a processing path conditionally |

The lesson presents the pipe operator as the declarative syntax for sequential chains. It does not demonstrate replacing every primitive with pipe syntax.

## Conclusion

Runnable primitives provide a way to organize AI application logic into reusable workflows. Rather than writing all the orchestration manually, we can compose task-specific Runnables and control how information moves through the application.

The most important concepts to remember are:

- **Sequence** controls the order of execution.
- **Parallel** allows independent tasks to process the same input.
- **Passthrough** preserves information.
- **Lambda** introduces custom Python logic.
- **Branch** adds conditional routing.
- **LCEL** makes sequential composition concise through the pipe operator.

Together, these concepts provide the foundation for building more involved LangChain applications, including workflows that combine multiple model calls, custom transformations, and conditional processing.
