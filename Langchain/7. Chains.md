## Introduction

When building applications with large language models (LLMs), a single model call is often only one part of the overall application. You might need to format a prompt, call a model, parse its response, summarize the result, or decide what should happen next.

This is where **chains** become useful.

In this tutorial, we'll start with a simple prompt-to-model pipeline, build a sequential workflow, run independent tasks in parallel, and finally create a conditional workflow that chooses a response based on sentiment.

### What you'll learn

- Why chains are useful in LLM applications.
- How to connect prompts, models, and output parsers using the pipe operator.
- How sequential and parallel execution differ.
- How to use structured output and conditional branching.
- How to combine smaller chains into a larger workflow.

## 1. Understanding Chains in LangChain

### Why do we need chains?

Imagine building an LLM application that accepts a question from a user, sends it to a language model, and displays the response.

Even this small application involves multiple operations:

- Designing a prompt.
- Collecting the user's input.
- Sending the formatted prompt to the model.
- Extracting the model's response.
- Displaying the result.

If you handle every operation manually, the code can become repetitive and harder to maintain as the application grows.

A chain allows you to connect these operations into a reusable pipeline. The output of one step can automatically become the input to the next step.

#### Manual approach

```text
Format prompt → Invoke model → Extract response → Display
```

Each operation must be coordinated by your code.

#### Chain approach

```text
Prompt → Model → Parser
```

Define the pipeline once, then invoke it with the input.

_**LangChain's runnable composition supports sequential and parallel execution, while `RunnableBranch` provides conditional routing.**_

## 2. Building Your First Chain

Let's build a small application that generates five interesting facts about a topic supplied by the user.

### Step 1: Create a prompt template

A prompt template defines the instructions that will be sent to the model. In this example, `{topic}` is the variable that will be filled with the user's input.

```python
from langchain_core.prompts import PromptTemplate

prompt = PromptTemplate(
    template="Generate five interesting facts about {topic}",
    input_variables=["topic"]
)
```

### Step 2: Create the model and parser

The model generates a response, while `StrOutputParser` extracts the textual output.

```python
from langchain_openai import ChatOpenAI
from langchain_core.output_parsers import StrOutputParser

model = ChatOpenAI()
parser = StrOutputParser()
```

### Step 3: Connect the components

LangChain Expression Language (LCEL) uses the pipe operator (`|`) to compose runnable components into a sequence.

```python
chain = prompt | model | parser
```

### Step 4: Invoke the chain

```python
result = chain.invoke({"topic": "cricket"})

print(result)
```

The input is passed to the prompt template, the formatted prompt is passed to the model, and the model's response is processed by the parser.

You can also inspect the chain's graph:

```python
chain.get_graph().print_ascii()
```

> **Remember:** `chain.invoke(...)` triggers the connected workflow. You provide the required initial input rather than manually invoking each component in the sequence.

## 3. Sequential Chains: When One Task Depends on Another

A sequential chain runs operations in order. This is useful when the next step requires the result of the previous step.

### Example: Generate a report and summarize it

Suppose the user enters `Unemployment in India`.

We want the application to:

1. Generate a detailed report on unemployment in India.
2. Pass that report to another prompt.
3. Generate a five-point summary.
4. Return the summary.

<img width="717" height="425" alt="image" src="https://github.com/user-attachments/assets/26bd88ce-1f7c-4584-9997-177712f13979" />


### Python code

```python
from langchain_openai import ChatOpenAI
from langchain_core.prompts import PromptTemplate
from langchain_core.output_parsers import StrOutputParser

model = ChatOpenAI()
parser = StrOutputParser()

prompt1 = PromptTemplate(
    template="Generate a detailed report on {topic}",
    input_variables=["topic"]
)

prompt2 = PromptTemplate(
    template=(
        "Generate a five-point summary from the "
        "following text:\n{text}"
    ),
    input_variables=["text"]
)

chain = prompt1 | model | parser | prompt2 | model | parser

result = chain.invoke({
    "topic": "Unemployment in India"
})

print(result)
```

### What makes this sequential?

The first model call generates the report. The parser converts that response into text, which becomes the input for the second prompt.

The second model call cannot perform its summarization task until the report has been generated.

```text
Input → Task 1 → Output 1 → Task 2 → Final output
```

## 4. Parallel Chains: Running Independent Tasks Together

Now consider a different problem.

A user provides a long document about linear regression. We want to generate:

- Short, simple notes.
- Five short question-and-answer pairs.

Both tasks use the same original document. Neither task needs to wait for the other to finish. This is a suitable use case for parallel execution.

### How `RunnableParallel` works

`RunnableParallel` accepts a mapping of runnable tasks, provides the same input to each task, and returns a mapping of their outputs.

<img width="710" height="346" alt="image" src="https://github.com/user-attachments/assets/c46bb5f3-dd5a-416e-add5-513fe80594bc" />


### Python implementation

```python
from langchain_openai import ChatOpenAI
from langchain_anthropic import ChatAnthropic
from langchain_core.prompts import PromptTemplate
from langchain_core.output_parsers import StrOutputParser
from langchain_core.runnables import RunnableParallel

# Models
model1 = ChatOpenAI()
model2 = ChatAnthropic()

parser = StrOutputParser()

# Prompt for notes
notes_prompt = PromptTemplate(
    template=(
        "Generate short and simple notes from "
        "the following text:\n{text}"
    ),
    input_variables=["text"]
)

# Prompt for quiz
quiz_prompt = PromptTemplate(
    template=(
        "Generate five short question-answer pairs "
        "from the following text:\n{text}"
    ),
    input_variables=["text"]
)

# Prompt to merge the results
merge_prompt = PromptTemplate(
    template=(
        "Merge the provided notes and quiz into "
        "a single document.\n\n"
        "Notes:\n{notes}\n\n"
        "Quiz:\n{quiz}"
    ),
    input_variables=["notes", "quiz"]
)

# Independent branches
notes_chain = notes_prompt | model1 | parser
quiz_chain = quiz_prompt | model2 | parser

parallel_chain = RunnableParallel(
    notes=notes_chain,
    quiz=quiz_chain
)

# Merge stage
merge_chain = merge_prompt | model1 | parser

# Complete workflow
chain = parallel_chain | merge_chain

result = chain.invoke({
    "text": "Your linear regression document goes here."
})

print(result)
```

> **Setup note:** This example uses OpenAI and Anthropic integrations. Install the relevant integration packages and configure credentials and supported model names for each provider. Exact model configuration can vary by provider and package version.

### Understanding the output mapping

The parallel stage returns a mapping conceptually similar to:

```python
{
    "notes": "Generated notes...",
    "quiz": "Generated question-answer pairs..."
}
```

The merge prompt expects those two keys. Therefore, the parallel stage can feed directly into the merge chain:

```python
chain = parallel_chain | merge_chain
```

This illustrates an important feature of chains: smaller workflows can be combined into a larger workflow.

## 5. Conditional Chains: Choosing a Path Based on a Condition

A conditional chain selects which processing path to execute based on a condition.

Let's use a customer-feedback example. A user submits feedback about a product. The application classifies the feedback as positive or negative and generates an appropriate response.

- **Positive feedback:** Generate a thank-you message.
- **Negative feedback:** Generate an empathetic response.
- **Unrecognized sentiment:** Return a default message.

### Architecture

<img width="727" height="377" alt="image" src="https://github.com/user-attachments/assets/bfb0df60-3b50-4007-b96d-82b6c8607e54" />


### Step 1: Define a structured sentiment model

A model might return different wordings for the same sentiment. For example, it could return `positive`, `The sentiment is positive`, or another variation.

The lesson uses Pydantic to constrain the output to the expected values.

```python
from pydantic import BaseModel, Field
from typing import Literal

class Feedback(BaseModel):
    sentiment: Literal["positive", "negative"] = Field(
        description="The sentiment of the feedback"
    )
```

The `Literal` type specifies the allowed sentiment values. This makes the classification result easier to use in a branch condition.

### Step 2: Create the classification chain

```python
from langchain_openai import ChatOpenAI
from langchain_core.prompts import PromptTemplate
from langchain_core.output_parsers import PydanticOutputParser

model = ChatOpenAI()

parser = PydanticOutputParser(
    pydantic_object=Feedback
)

classification_prompt = PromptTemplate(
    template=(
        "Classify the sentiment of the following "
        "feedback as positive or negative.\n"
        "{feedback}\n"
        "{format_instructions}"
    ),
    input_variables=["feedback"],
    partial_variables={
        "format_instructions":
            parser.get_format_instructions()
    }
)

classification_chain = (
    classification_prompt | model | parser
)

result = classification_chain.invoke({
    "feedback": "This is a terrible smartphone."
})

print(result.sentiment)
```

The parsed result exposes the sentiment as a field:

```python
result.sentiment
```

For the example feedback, the intended classification is `negative`.

### Step 3: Create the response chains

```python
from langchain_core.output_parsers import StrOutputParser

string_parser = StrOutputParser()

positive_prompt = PromptTemplate(
    template=(
        "Write an appropriate thank-you response "
        "to this positive feedback:\n{feedback}"
    ),
    input_variables=["feedback"]
)

negative_prompt = PromptTemplate(
    template=(
        "Write an empathetic and appropriate response "
        "to this negative feedback:\n{feedback}"
    ),
    input_variables=["feedback"]
)

positive_chain = positive_prompt | model | string_parser
negative_chain = negative_prompt | model | string_parser
```

Each response chain accepts the feedback and generates a response suitable for that sentiment.

### Step 4: Create the conditional branch

`RunnableBranch` accepts condition-and-runnable pairs and a default runnable. It evaluates the conditions in order and runs the first matching branch.

```python
from langchain_core.runnables import (
    RunnableBranch,
    RunnableLambda
)

branch_chain = RunnableBranch(
    (
        lambda x: x["sentiment"].sentiment == "positive",
        positive_chain
    ),
    (
        lambda x: x["sentiment"].sentiment == "negative",
        negative_chain
    ),
    RunnableLambda(
        lambda x: "Could not determine sentiment."
    )
)
```

The logic is equivalent to an `if`/`elif`/`else` structure:

```python
if sentiment == "positive":
    # Run the positive response chain
    ...

elif sentiment == "negative":
    # Run the negative response chain
    ...

else:
    # Run the default branch
    ...
```

### Step 5: Connect the classification and response stages

We need to preserve the original feedback while adding the classification result. `RunnablePassthrough.assign` allows us to add a field to the input mapping.

```python
from langchain_core.runnables import RunnablePassthrough

full_chain = (
    RunnablePassthrough.assign(
        sentiment=classification_chain
    )
    | branch_chain
)

response = full_chain.invoke({
    "feedback": "This is a terrible smartphone."
})

print(response)
```

The workflow now performs the following operations:

1. Receives the feedback.
2. Classifies the sentiment.
3. Adds the classification to the input mapping.
4. Evaluates the branch conditions.
5. Executes the selected response chain.
6. Returns the generated response.

For negative feedback, the application might generate an empathetic message such as an apology for the customer's experience. For positive feedback, it might generate a thank-you message.

> **Important distinction:** A parallel chain runs independent tasks together. A conditional chain chooses a path based on a condition. These are different execution patterns and solve different workflow problems.

## Conclusion

Chains are a fundamental building block for composing LLM applications in LangChain. They let you connect prompts, models, parsers, and other runnable components into workflows that can be invoked as a unit.

Key concepts from this lesson:

- Use the pipe operator (`|`) to connect components into a sequence.
- Use sequential execution when the next task needs the previous task's output.
- Use `RunnableParallel` when independent tasks can execute concurrently.
- Use `RunnableBranch` when the application must choose a processing path.
- Use structured output when downstream logic depends on predictable values.
- Use `get_graph().print_ascii()` to inspect the structure of a chain.

The next concept introduced by the lesson is **Runnables**: what they are, how they work, and how they support the construction and execution of chains.
