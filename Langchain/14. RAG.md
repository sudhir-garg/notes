# 1. Introduction and RAG recap

## What is RAG?

Retrieval-Augmented Generation (RAG) is a technique for improving the responses of a Large Language Model (LLM) by supplying relevant external information at the time a question is asked.

Instead of relying only on information encoded in the model's parameters, a RAG system retrieves relevant information from an external knowledge base and includes it in the prompt sent to the LLM.

This lecture introduces RAG through three questions:

- Why: Why is RAG needed when LLMs already contain substantial knowledge?
- What: What exactly is RAG, and how does it differ from fine-tuning and in-context learning?
- How: How does a RAG-based application retrieve information and generate an answer?

# 2. Why do we need RAG?

## 2.1 How does an LLM store knowledge?

An LLM is a neural network trained on large amounts of data. During training, it learns patterns and information represented in its parameters, which are its weights and biases.

The lecture refers to knowledge stored in model parameters as parametric knowledge.

When a user submits a prompt, the model uses its learned representations to generate a response.

<img width="723" height="294" alt="image" src="https://github.com/user-attachments/assets/283982a7-18fa-41b6-8330-50a1676bc6c4" />


This approach works for many questions. However, the lecture identifies three important situations in which relying on parametric knowledge alone may not be sufficient.

## 2.2 Problem 1: Private or domain-specific data

Suppose an educational website contains several hours of course lectures. A student asks an LLM:

> What did the instructor explain about gradient descent at minute 15 of this lecture?

A general-purpose model may not have access to that private lecture transcript. It cannot reliably answer a question about information it has never received.

The same issue can arise with:

- Internal company documents.
- Private course materials.
- Proprietary databases.
- Organization-specific procedures.

**Core problem**: The information required to answer the question is not necessarily part of the LLM's parametric knowledge.

## 2.3 Problem 2: Recent information

An LLM's training data has a cutoff. Information that appeared after its training may not be represented in its parameters.

For example:

> What was the latest announcement made by a company today?

A model without access to current information cannot reliably answer this question from its training knowledge alone.

The lecture notes that systems with internet-search capabilities can obtain information beyond their original training data. However, a standalone model without such access may lack the required recent information.

**Core problem**: The model's stored knowledge may be outdated.

## 2.4 Problem 3: Hallucination

A hallucination occurs when an LLM generates information that is factually incorrect or unsupported, potentially presenting it with confidence.

For example, a model might invent a historical detail about a well-known scientist rather than acknowledge uncertainty.

The lecture emphasizes that language generation is probabilistic, so a response generated from learned patterns is not automatically guaranteed to be factually correct.

**Core problem**: The model can generate plausible-sounding information that is not true.

## The three problems at a glance

| Problem       | Why parametric knowledge alone may fail                              |
| ------------- | -------------------------------------------------------------------- |
| Private data  | The model may never have seen the required information.              |
| Recent data   | The information may have appeared after the model's training cutoff. |
| Hallucination | The model may produce incorrect or fabricated information.           |

The lecture next examines fine-tuning as one way to address these limitations.

# 3. Understanding fine-tuning

## 3.1 What is fine-tuning?

Fine-tuning is the process of taking a pretrained LLM and training it further on a smaller, domain-specific dataset.

The goal is to adapt the model to a particular domain or task.

For example, if a model needs to work with medical terminology, it can be further trained on medical data.

The lecture uses an engineering graduate joining a company as an analogy:

- Engineering education represents pretraining.
- Company-specific training represents fine-tuning.
- The graduate already has general knowledge but learns how to perform a particular job.

## 3.4 How fine-tuning addresses the three problems

| Problem       | How fine-tuning may help                                                                        |
| ------------- | ----------------------------------------------------------------------------------------------- |
| Private data  | Training on domain data can incorporate information from that data into the model.              |
| Recent data   | The model can be trained again using newly collected information.                               |
| Hallucination | Training examples can teach the model to acknowledge uncertainty and avoid unsupported answers. |

## 3.5 Limitations of fine-tuning

The lecture identifies three major challenges:

1. Computational expense: Training a large model can require substantial computing resources and money.
2. Technical expertise: Fine-tuning requires suitable engineering and data-science expertise.
3. Repeated updates: When information changes frequently, the model may need repeated training. Removing outdated knowledge can also be difficult.

These limitations motivate the use of in-context learning and RAG.

# 4. In-context learning and few-shot prompting

## 4.1 What is in-context learning?

In-context learning is the ability of an LLM to perform a task by using examples or instructions provided in its prompt, without updating its model weights during that interaction.

The lecture explains this using sentiment analysis.

<img width="712" height="434" alt="image" src="https://github.com/user-attachments/assets/2772c952-9f6d-491d-bf04-daf533260302" />


The model has not been retrained for this specific request. Instead, it uses the examples included in the prompt to guide its response.

## 4.2 Few-shot prompting

Few-shot prompting means including a small number of examples in the prompt to demonstrate the desired task.

Examples can be used for tasks such as:

- Sentiment analysis.
- Named entity recognition.
- Mathematical problem solving.
- Domain-specific question answering.

## 4.3 Emergent capabilities and the historical perspective

The lecture describes in-context learning as an emergent capability observed as language models grew in scale and complexity.

It discusses GPT-3, with approximately 175 billion parameters, and the research paper Language Models are Few-Shot Learners.

The paper is presented in the lecture as a landmark work that helped popularize the study of few-shot learning in language models.

The lecture also notes that in-context learning does not guarantee strong performance on every task, and discusses supervised fine-tuning and RLHF as techniques used to improve model behaviour.

## 4.4 From examples to relevant context

Few-shot prompting provides examples of how to solve a task. RAG takes a related idea further: instead of supplying only examples, a system can retrieve information that is directly relevant to the user's question.

For example, a student asking about gradient descent can receive the relevant portion of a lecture transcript in the prompt.

That is the central transition from in-context learning to RAG.

# 5. What is Retrieval-Augmented Generation?

## 5.1 Definition

Retrieval-Augmented Generation (RAG) is an approach in which relevant information is retrieved from an external knowledge source and provided to an LLM as additional context when generating an answer.

The lecture's central idea is:

> Give the model extra information at the time the question is asked.

This means the model can use both:

- Its parametric knowledge.
- The retrieved context supplied with the current prompt.

## 5.2 Example: a course-support chatbot

Imagine an educational website containing a two-hour lecture on linear regression.

A student asks:

> How does the optimization step work in gradient descent?

The system does not need to send the entire two-hour transcript to the LLM. Instead, it retrieves the relevant sections, such as the portions covering gradient descent, and supplies those sections alongside the question.

## 5.3 Why RAG is useful

| Requirement         | How RAG helps                                                                                              |
| ------------------- | ---------------------------------------------------------------------------------------------------------- |
| Private information | The external knowledge base can contain the organization's own documents.                                  |
| Recent information  | New or updated documents can be added to the knowledge base and indexed.                                   |
| Grounded responses  | The prompt can instruct the LLM to answer using retrieved context and acknowledge when it is insufficient. |

RAG can reduce reliance on model memory for these questions, but it does not guarantee that every generated response will be correct.

# 7. Indexing: preparing the knowledge base

## 7.1 What is indexing?

Indexing is the process of preparing a knowledge base so that it can be searched efficiently when a user submits a query.

In RAG, the external knowledge base provides the information that may later be inserted into the LLM's prompt.

The lecture describes four main activities within indexing:

1. Document ingestion.
2. Text chunking.
3. Embedding generation.
4. Storage in a vector store.

## 7.2 Step 1 — Document ingestion

Document ingestion means fetching or loading source information into the system so it can be processed.

Possible sources include:

- PDF files.
- YouTube lecture transcripts.
- Websites.
- Google Drive documents.
- Documents stored on AWS S3.
- Company knowledge repositories.

LangChain document loaders can help load information from these different sources.

After ingestion, the content can be represented as text and processed further.

## 7.3 Step 2 — Text chunking

A large document is divided into smaller pieces called chunks.

The lecture gives two main reasons for chunking:

- An entire large document may exceed the LLM's context-length limit.
- Searching a very large document as a single unit may not provide sufficiently useful retrieval results.

Chunks should ideally preserve meaningful information. For example, a chunk discussing gradient descent should contain a coherent section about gradient descent rather than an arbitrary fragment that cuts off the explanation.

LangChain provides different text-splitting approaches, including:

- Recursive character text splitting.
- Semantic chunking.
- HTML-specific splitting.
- Markdown-specific splitting.

## 7.4 Step 3 — Generate embeddings

An embedding model converts each text chunk into a dense numerical vector that represents aspects of its meaning.

For example:

<img width="717" height="297" alt="image" src="https://github.com/user-attachments/assets/bfc6e652-15ce-43b6-930e-5a597599b285" />

## 7.5 Step 4 — Store the vectors and original text

Each embedding is stored alongside its corresponding text chunk and metadata.

The lecture mentions vector-store options including FAISS and Chroma for local use, and Pinecone, Weaviate, Milvus, and Qdrant for cloud-oriented deployments.

The resulting vector store becomes the external knowledge base used during retrieval.

# 8. Retrieval: finding relevant information

## 8.1 What is retrieval?

Retrieval is the real-time process of finding the most relevant information from a prepared index based on the user's question.

Suppose the knowledge base contains chunks about:

- Ordinary least squares (OLS).
- Multiple linear regression.
- Gradient descent.
- Other optimization methods.

If the user asks about gradient descent, the retriever should find the chunks that best address that topic.

## 8.3 Similarity search and other retrieval strategies

The lecture connects retrieval with techniques discussed in the earlier retriever lessons.

Examples include:

- Similarity search.
- Maximum Marginal Relevance (MMR).
- Contextual compression.
- Other advanced search and reranking techniques.

The specific strategy determines how candidate documents are selected, ordered, and returned.

## 8.4 Why not send the entire knowledge base?

A large knowledge base may contain far more information than is relevant to a particular question.

Retrieval allows the system to select a smaller collection of useful chunks instead of sending every document to the LLM.

This helps focus the prompt on information related to the current query.

# 9. Augmentation: constructing the prompt

## 9.1 What is augmentation?

Augmentation is the stage where the user's query is combined with the retrieved context to construct the prompt sent to the LLM.

The context supplies additional information that was not necessarily present in the model's original parametric knowledge.

## 9.2 Example of an augmented prompt

Consider a question about gradient descent.

```
You are a helpful assistant.

Answer the question using only the
provided context.

If the context is insufficient, say:
"I don't know."

Context:
[Relevant transcript chunks about
gradient descent]

Question:
How does the optimization step work
in gradient descent?
```

The prompt provides:

1. An instruction describing how the LLM should answer.
2. Retrieved information relevant to the question.
3. The user's original question.

The lecture emphasizes instructing the model to acknowledge insufficient context rather than inventing an answer.

# 10. Generation: producing the answer

## 10.1 What happens during generation?

The augmented prompt is sent to the LLM.

The model then uses its text-generation capabilities to produce a response based on the prompt, including the supplied context and its learned representations.

<img width="722" height="299" alt="image" src="https://github.com/user-attachments/assets/99101ad0-f930-4b69-aaf2-8ce665625aaf" />


The generated answer is returned to the user.

## 10.2 Grounding and hallucination reduction

The lecture describes grounding as connecting the model's response to the retrieved context.

A prompt can instruct the model to:

- Answer using the supplied context.
- Avoid introducing unsupported facts.
- Say that it does not know when the context is insufficient.

These instructions can reduce hallucinations, but they cannot guarantee their complete elimination. Retrieval quality and the model's interpretation of the context still matter.

# 12. RAG implementation using LangChain

The lecture's practical follow-up is to build a RAG system from scratch using LangChain. The following code is an illustrative implementation of the concepts explained in the lecture; it is not a verbatim code listing from the transcript.

## 12.1 Install the packages

``` bash
pip install -U langchain langchain-community \
    langchain-openai langchain-chroma langchain-text-splitters
```

## 12.2 Load, split, embed, and index documents

This example uses a text file as the source. Other document loaders can be substituted for PDFs, websites, or transcripts.

``` python
from langchain_core.documents import Document
from langchain_text_splitters import RecursiveCharacterTextSplitter
from langchain_openai import OpenAIEmbeddings
from langchain_chroma import Chroma

# 1. Load source content.
with open("lecture.txt", "r", encoding="utf-8") as f:
    text = f.read()

documents = [
    Document(
        page_content=text,
        metadata={"source": "lecture.txt"}
    )
]

# 2. Split the document into chunks.
splitter = RecursiveCharacterTextSplitter(
    chunk_size=800,
    chunk_overlap=120
)

chunks = splitter.split_documents(documents)

# 3. Create the embedding model.
embeddings = OpenAIEmbeddings(
    model="text-embedding-3-small"
)

# 4. Store chunk text and embeddings.
vector_store = Chroma.from_documents(
    documents=chunks,
    embedding=embeddings,
    collection_name="lecture_knowledge"
)

print(f"Indexed {len(chunks)} chunks.")
```

The chunk size and overlap are illustrative settings and should be tuned for the documents and retrieval task. Configure the required model credentials before running the example.

## 12.3 Retrieve relevant chunks

```
# Create a retriever from the vector store.
retriever = vector_store.as_retriever(
    search_kwargs={"k": 3}
)

question = "How does gradient descent optimize a model?"

# Retrieve the most relevant chunks.
retrieved_docs = retriever.invoke(question)

for i, doc in enumerate(retrieved_docs, start=1):
    print(f"Chunk {i}:")
    print(doc.page_content)
    print()
```

The retriever returns document chunks that can be used as the context for the answer.

## 12.4 Construct the prompt and generate a response

```
from langchain_openai import ChatOpenAI
from langchain_core.prompts import ChatPromptTemplate

llm = ChatOpenAI(model="gpt-4o-mini", temperature=0)

prompt = ChatPromptTemplate.from_template("""
You are a helpful assistant.

Answer using only the provided context.
If the context is insufficient, say "I don't know."

Context:
{context}

Question:
{question}
""")

context = "\n\n".join(
    doc.page_content for doc in retrieved_docs
)

messages = prompt.format_messages(
    context=context,
    question=question
)

response = llm.invoke(messages)

print(response.content)
```
