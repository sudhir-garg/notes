## Why Do We Need Output Parsers?

When you call a chat model, the response often contains more than the plain text you want to use. The model may return an AI message object with content and additional metadata.

For example, suppose you ask the model to summarize a topic. You might only need the summary text—not the rest of the message information.

Or imagine you’re building an application that expects a person’s details in a predictable structure:

```json
{
  "name": "Aarav",
  "age": 25,
  "city": "Delhi"
}
```

If the model returns `"age": "25 years"` instead of an integer, your application may have to handle that unexpected value.

Output parsers help you process model responses into a form that is more useful to your application. Different parsers serve different needs, from extracting plain text to producing structured data.

- **Prompt:** Tell the model what you want it to do.

## 2. `StrOutputParser`: When You Just Need Text

The `StrOutputParser` is the simplest parser discussed in the lesson. Its job is to take the model’s response and return the textual content as a string.

This is useful when you want to pass a model’s response into another step—for example, asking one model to produce a report and then asking another step to summarize that report.

### Example

```python
from langchain_core.output_parsers import StrOutputParser
from langchain_core.prompts import ChatPromptTemplate
from langchain_openai import ChatOpenAI

model = ChatOpenAI()

prompt = ChatPromptTemplate.from_template(
    "Write a short report about {topic}."
)

parser = StrOutputParser()

chain = prompt | model | parser

result = chain.invoke({"topic": "black holes"})

print(result)
```

Here’s what happens:

1. The prompt is filled with the topic.
2. The chat model generates a response.
3. `StrOutputParser` extracts the textual content.
4. The chain returns that content as a string.

**Key idea:** Use `StrOutputParser` when the next step needs ordinary text rather than a structured object.

---

## 3. `JsonOutputParser`: When You Need JSON

Now suppose your application needs a JSON response instead of a paragraph. That’s where `JsonOutputParser` becomes useful.

It helps guide the model to return JSON-formatted output and parses the response into a Python data structure, such as a dictionary.

### Example

```python
from langchain_core.output_parsers import JsonOutputParser
from langchain_core.prompts import ChatPromptTemplate
from langchain_openai import ChatOpenAI

model = ChatOpenAI()
parser = JsonOutputParser()

prompt = ChatPromptTemplate.from_template(
    """
    Give information about a person named {name}.

    {format_instructions}
    """
)

prompt = prompt.partial(
    format_instructions=parser.get_format_instructions()
)

chain = prompt | model | parser

result = chain.invoke({"name": "Aarav"})

print(result)
print(type(result))
```

The important part is:

```python
parser.get_format_instructions()
```

These instructions can be included in the prompt to tell the model what output format is expected.

If the response is valid JSON, the parser can convert it into a Python object—for example, a dictionary.

### An important distinction

`JsonOutputParser` helps obtain JSON output, but it does **not** provide the same schema-based data validation as a Pydantic model. If your application needs strict field types or constraints, consider a parser that supports those requirements.

---

## 4. `StructuredOutputParser`: When You Want Specific Fields

What if you don’t just want JSON—you want JSON with particular fields?

For example, you might want a response containing three facts, each stored under a known key. The `StructuredOutputParser` lets you define a set of response schemas and use them to guide the model’s output.

### Example

```python
from langchain.output_parsers import (
    ResponseSchema,
    StructuredOutputParser,
)

response_schemas = [
    ResponseSchema(
        name="fact_1",
        description="The first fact"
    ),
    ResponseSchema(
        name="fact_2",
        description="The second fact"
    ),
    ResponseSchema(
        name="fact_3",
        description="The third fact"
    ),
]

parser = StructuredOutputParser.from_response_schemas(
    response_schemas
)

format_instructions = parser.get_format_instructions()
```

You can then include `format_instructions` in your prompt so the model knows which fields to return.

After generating a response, pass it to the parser:

```python
parsed_result = parser.parse(model_response)
```

The result is structured data organized around the fields you specified.

### What should you remember?

The main benefit is that you can describe the expected structure in advance. However, defining fields is not the same as enforcing every data type and validation rule at runtime. That distinction leads us to the next parser.

## 5. `PydanticOutputParser`: When You Need Schema Validation

Let’s say your application expects the following:

- `name` must be a string.
- `age` must be an integer greater than 18.
- `city` must be a string.

Simply asking the model to follow those rules in a prompt may not be enough. You need a way to represent the schema and validate the parsed result.

The `PydanticOutputParser` works with a Pydantic model to define the expected data structure and validate the resulting values.

### Step 1: Define a Pydantic model

```python
from pydantic import BaseModel, Field

class Person(BaseModel):
    name: str
    age: int = Field(gt=18)
    city: str
```

This model describes the expected fields and their types. The `Field(gt=18)` constraint specifies that `age` must be greater than 18.

### Step 2: Create the parser

```python
from langchain_core.output_parsers import PydanticOutputParser

parser = PydanticOutputParser(pydantic_object=Person)

format_instructions = parser.get_format_instructions()
```

Include those format instructions in the prompt you send to the model.

### Step 3: Parse the response

```python
parsed_person = parser.parse(model_response)

print(parsed_person)
print(parsed_person.name)
print(parsed_person.age)
```

The parser produces a Pydantic model instance when parsing and validation succeed. If the returned data does not satisfy the model’s requirements, validation can fail rather than silently treating an invalid value as acceptable.

**Key idea:** Use a Pydantic-based parser when your application needs defined fields, types, and validation constraints.

## 6. Comparing the Parsers

Now that we’ve explored the main parsers, let’s compare their roles.

| Parser | Main purpose | What you get |
|---|---|---|
| `StrOutputParser` | Extract textual content | A string |
| `JsonOutputParser` | Parse JSON-formatted output | A Python data structure, such as a dictionary |
| `StructuredOutputParser` | Guide output around predefined fields | Structured data using the specified fields |
| `PydanticOutputParser` | Parse data against a Pydantic model | A validated Pydantic model instance when validation succeeds |

The important difference is not simply whether the output looks like JSON. It’s how much structure and validation your application requires.

## 7. Other Output Parsers to Know About

LangChain also provides other parsers for particular output formats and use cases. The lesson mentions examples such as:

- **CSV parser** — for comma-separated values.
- **List parser** — for list-like output.
- **Markdown parser** — for Markdown-oriented content.
- **Numbered-list parser** — for numbered items.
- **XML parser** — for XML-formatted output.
- **Datetime parser** — for date and time values.
- **Output-fixing parser** — a parser-related option for attempting to correct malformed output.

The appropriate choice depends on the format your application expects and the degree of validation it needs.

## 8. A Simple Way to Choose

When building a LangChain chain, ask yourself what the next step needs to receive.

| If the next step needs… | Consider using… |
|---|---|
| Plain text | `StrOutputParser` |
| JSON data | `JsonOutputParser` |
| Data arranged around specified fields | `StructuredOutputParser` |
| A schema with types and validation rules | `PydanticOutputParser` |

## 9. StructuredOutput vs Parsers

- **Structured output** is the goal and model-facing capability: obtain a response that conforms to a defined schema or format.
- **Output parsers** are components that process a model response and convert it into a useful representation, such as a string, JSON object, or validated Pydantic model.

They are related, not mutually exclusive. LangChain's structured-output APIs may perform parsing as part of the process.

| Feature | Structured output | Output parsers |
|---|---|---|
| Main purpose | Guide the model toward a specified response schema | Convert or validate the response produced by the model |
| Main focus | Output generation and schema conformance | Post-generation parsing and transformation |
| Typical mechanisms | Provider-native structured output, tool/function calling, or other integration-supported strategy | Text extraction, JSON parsing, Pydantic validation, list parsing, and related transformations |
| Typical result | A schema-shaped dictionary or model instance, depending on the integration | A string, dictionary, Pydantic instance, list, or another parsed value |
| Examples | `llm.with_structured_output(Person)` | `StrOutputParser`, `JsonOutputParser`, `PydanticOutputParser` |
| Main limitation | Availability and behavior vary by model/provider integration and method | Parsing depends on the response matching what the parser expects; errors need handling |

- Use **`with_structured_output()`** when your chosen model integration supports an appropriate structured-output strategy and you want a schema-based result.
- Use an **output parser** when you need to extract or validate content from ordinary model text, when native structured output is unavailable, or when you need additional post-processing.
- In either case, design for errors: validate important fields and handle malformed output.

  
## 10. Final Takeaways

Output parsers help bridge the gap between a language model’s response and the representation your application needs.

- `StrOutputParser` extracts text.
- `JsonOutputParser` helps produce and parse JSON.
- `StructuredOutputParser` lets you specify the fields you expect.
- `PydanticOutputParser` uses a Pydantic model to support typed, validated data.

The central lesson is to choose a parser based on the requirements of the next step in your application. If all you need is text, a simple string parser may be enough. If your application depends on predictable fields and valid types, a schema-based approach may be more appropriate.
