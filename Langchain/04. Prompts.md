## 1. Quick recap and learning goals

The tutorial places prompts within the LangChain components introduced
earlier:

-   The previous lesson covered models.
-   This lesson covers prompts and the classes used to create them.
-   The goal is to understand **why** prompts need structure and
    **when** to use each prompt-related class.

## 2. What is a prompt?

A **prompt** is the message or input sent to a language model.

For example:

``` python
response = model.invoke("Write a five-line poem about cricket.")
```

The text passed to `invoke()` is the prompt.

Prompts can be text-based or multimodal. A multimodal prompt may include
images, audio, or video, but this lesson concentrates on text prompts.

### Why prompts matter

The model's output can change significantly when the prompt changes.
Prompt design therefore affects the behavior and consistency of an LLM
application.

## 3. Temperature and output variability

Temperature is a model parameter that affects the variability of
generated responses.

-   A **low temperature** (near `0`) generally makes output more
    consistent and predictable.
-   A **higher temperature** generally allows more variation and
    creative responses.

Example:

``` python
from langchain_openai import ChatOpenAI

model = ChatOpenAI(
    model="gpt-4",
    temperature=0
)

response = model.invoke("Write a five-line poem about cricket.")
print(response.content)
```

Changing `temperature` can produce different responses for the same
prompt. Exact behavior and supported ranges depend on the
model/provider; temperature `0` does not guarantee identical results in
every system.

**Practical choice:** - Prefer lower temperature when consistency is
important. - Consider a higher temperature when variety or creativity is
desired.

## 4. Static prompts vs. dynamic prompts

### Static prompt

A static prompt is written directly into the code or supplied in full by
the user.

``` python
response = model.invoke(
    "Summarize the Attention Is All You Need paper in five lines."
)
```

If the user wants a different paper, style, or length, they may need to
write a new prompt.

**Problem:** letting users freely write the entire prompt gives them
broad control over its wording. Small changes can lead to inconsistent
output or unintended results.

### Dynamic prompt

A dynamic prompt uses a predefined template with placeholders. The
application gathers values from the user and inserts them into the
template.

For example, a research summarizer can collect:

-   Paper name
-   Explanation style (for example, simple, math-heavy, or
    code-oriented)
-   Explanation length (short, medium, or long)

The application then fills the placeholders while keeping the core
instructions consistent.

``` text
Summarize the research paper {paper_input}.
Use a {style_input} explanation.
Make the summary {length_input}.
Include relevant equations and intuitive explanations when applicable.
If the paper does not provide enough information, say so rather than inventing details.
```
``` python
prompt = template.invoke({
    "paper_input": paper,
    "style_input": style,
    "length_input": length
})
```
### Flow

``` text
User selects paper, style, and length
                 |
                 v
         Fill the template
                 |
                 v
          Create the prompt
                 |
                 v
          Send it to the model
                 |
                 v
          Display the response
```

Dynamic prompts let the application offer user choices while preserving
a consistent prompt structure.

## 6. PromptTemplate

`PromptTemplate` is used to create a reusable text prompt containing
variables.

``` python
from langchain_core.prompts import PromptTemplate

template = PromptTemplate(
    template=(
        "Summarize {paper_input} in a {length_input} format. "
        "Use a {style_input} explanation."
    ),
    input_variables=["paper_input", "style_input", "length_input"]
)

prompt = template.invoke({
    "paper_input": "Attention Is All You Need",
    "style_input": "code-oriented",
    "length_input": "medium"
})

print(prompt)
```

The values supplied to `invoke()` fill the template's placeholders.

### Template variables

In this example, the variables are:

-   `paper_input`
-   `style_input`
-   `length_input`

Variable names in the input dictionary must correspond to the
placeholders expected by the template.

## 7. Why use PromptTemplate instead of f-strings?

Python f-strings can also insert values into strings:

``` python
paper_input = "Attention Is All You Need"
style_input = "simple"
length_input = "short"

prompt = (
    f"Summarize {paper_input} in a {length_input} format "
    f"using a {style_input} explanation."
)
```

The tutorial highlights several benefits of using `PromptTemplate`:

1.  **Validation:** template configuration can detect missing or
    unexpected variables when validation is enabled.
2.  **Reuse:** a template can be defined once and reused in different
    parts of an application.
3.  **Serialization:** templates can be saved and loaded rather than
    being embedded repeatedly in code.
4.  **Chain integration:** prompt templates can be composed with models
    and other steps in LangChain workflows.

F-strings remain useful for ordinary Python string formatting;
`PromptTemplate` adds LangChain-specific structure and integration.

## 8. Saving and loading prompt templates

A template can be serialized and loaded again. The tutorial demonstrates
the general pattern:

``` python
template.save("research_prompt.json")
```

Then load it:

``` python
from langchain_core.prompts import load_prompt

loaded_template = load_prompt("research_prompt.json")
```

This can help separate prompt design from application logic. Exact
serialization support can depend on the template type and LangChain
version.

## 9. Connecting a prompt to a model with LCEL

LangChain Expression Language (LCEL) uses the pipe operator (`|`) to
compose runnable components.

``` python
chain = template | model

response = chain.invoke({
    "paper_input": "Attention Is All You Need",
    "style_input": "simple and intuitive",
    "length_input": "short"
})

print(response.content)
```

Conceptually:

``` text
Input dictionary -> PromptTemplate -> Model -> Model response
```

This composition avoids manually invoking the template and then
separately passing the formatted prompt to the model.

## 10. Chatbots and conversation history

A single prompt can be enough for a one-off request, such as summarizing
a paper. A chatbot, however, usually has a multi-turn conversation.

For example:

1.  User: "Hi, how are you?"
2.  Assistant: "I'm doing well. How can I help?"
3.  User: "I need help with my homework."
4.  Assistant: "What do you need help with?"

To respond coherently, the model may need relevant previous messages.
Applications commonly maintain conversation history and include it in
later model calls.

### Why history matters

Imagine a customer asks for a refund, receives confirmation, and returns
later asking, "Where is my refund?" Without the earlier messages, the
model may not know what refund the user means.

The application should retrieve the relevant conversation history and
provide it as context. A real application may store that history in a
database; the tutorial illustrates the idea with a text file.

Example:

``` python
from langchain_core.messages import (
    SystemMessage,
    HumanMessage,
    AIMessage,
)

messages = [
    SystemMessage(content="You are a helpful assistant."),
```

## 12. ChatPromptTemplate

`ChatPromptTemplate` creates a **list of chat messages** with
placeholders. Use it when the model input is a structured conversation
rather than one standalone text prompt.

<img width="686" height="149" alt="image" src="https://github.com/user-attachments/assets/3d75b965-fa43-460b-8ad6-b657439b0fa3" />


``` python
from langchain_core.prompts import ChatPromptTemplate

chat_template = ChatPromptTemplate.from_messages([
    ("system", "You are a helpful {domain} expert."),
    ("human", "Explain {topic} in simple terms.")
])

prompt_value = chat_template.invoke({
    "domain": "cricket",
    "topic": "a googly"
})

print(prompt_value)
```

Here, both the system instruction and the human message are dynamic.

A tuple such as `("system", "...")` or `("human", "...")` specifies the
message role and template text. `ChatPromptTemplate` formats the
supplied variables into the corresponding messages.

## 13. MessagesPlaceholder

`MessagesPlaceholder` is a special placeholder inside a chat prompt
template. It allows a list of messages---often conversation history---to
be inserted at runtime.

<img width="714" height="315" alt="image" src="https://github.com/user-attachments/assets/8963ffef-89bd-497d-b6ed-1b99be86bd2a" />

**Example: customer support prompt**

``` python
from langchain_core.prompts import (
    ChatPromptTemplate,
    MessagesPlaceholder,
)

chat_template = ChatPromptTemplate.from_messages([
    ("system", "You are a helpful customer support agent."),
    MessagesPlaceholder(variable_name="chat_history"),
    ("human", "{query}")
])
```

The application can supply prior messages using the `chat_history`
variable:

``` python
from langchain_core.messages import HumanMessage, AIMessage

history = [
    HumanMessage(content="I want to request a refund for order 12345."),
    AIMessage(content="Your refund request has been initiated."),
]

prompt_value = chat_template.invoke({
    "chat_history": history,
    "query": "Where is my refund?"
})

print(prompt_value)
```

The resulting prompt contains, in order:

1.  The system instruction
2.  The previous conversation messages
3.  The current user query

This gives the model the context needed to interpret the latest
question. The application is responsible for retrieving and passing the
correct history.

## 14. Single message vs. list of messages

  -----------------------------------------------------------------------
 <img width="729" height="366" alt="image" src="https://github.com/user-attachments/assets/bd3b1973-d7c7-4ba2-8689-f706fb9e5100" />


The tutorial's key distinction:

-   `PromptTemplate` is for creating a dynamic **text prompt**.
-   `ChatPromptTemplate` is for creating a dynamic **set of chat
    messages**.
-   `MessagesPlaceholder` inserts a variable-length set of messages,
    such as stored chat history, into a chat template.

## 15. Key takeaways

-   A prompt is the input sent to a language model, and prompt wording
    can influence the response.
-   Temperature affects response variability; lower values generally
    favor consistency, while higher values allow more variation.
-   Static prompts are fixed or user-written in full. Dynamic prompts
    use a controlled template and runtime values.
-   `PromptTemplate` provides reusable text templates, variable
    handling, validation options, and integration with LangChain
    workflows.
-   LCEL's `|` operator can connect a prompt template to a model.
-   Chat conversations use role-labeled messages such as system, human,
    and AI messages.
-   `ChatPromptTemplate` builds dynamic message lists.
-   `MessagesPlaceholder` inserts stored conversation history or another
    list of messages at runtime.
-   For a chatbot to use previous context, the application must
    maintain, retrieve, and pass the relevant conversation history.
