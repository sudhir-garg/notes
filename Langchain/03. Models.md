## 1. Language Models
Language models take text as input, process it, and return a text response. LangChain categorizes these into two distinct types:

| Feature | LLMs (Large Language Models) | Chat Models |
| :--- | :--- | :--- |
| **Primary Use Case** | General purpose (text generation, summarization, code). | Conversational tasks (chatbots, agents, AI tutors). |
| **Input/Output** | Takes a single plain text string and returns a plain text string. | Takes a sequence of messages and returns chat messages. |
| **Memory & Context** | No native memory concept; forgets previous interactions. | Supports conversational history and multi-turn conversations. |
| **Role Awareness** | Cannot assign specific roles. | Can assign system-level roles (e.g., "You are a qualified doctor"). |
| **LangChain Support** | Being phased out; not recommended for new projects. | The recommended standard for modern GenAI applications. |

**Key Tuning Parameters:**
*   **Temperature (0 to ~2):** Controls the randomness and creativity of the output. Use values between 0.0–0.3 for factual/deterministic tasks (like coding), 0.5–0.7 for general explanations, and 0.9–1.5+ for creative writing or brainstorming.
*   **Max Completion Tokens:** Restricts the maximum number of tokens (roughly words) the model can return, which is highly useful for controlling API costs.

### Closed-Source (Proprietary) Models
Closed-source models (like OpenAI's GPT, Anthropic's Claude, and Google's Gemini) require paid API keys and process data on external servers. LangChain provides a highly consistent interface to interact with them. 

```python
# Required: .env file containing OPENAI_API_KEY, ANTHROPIC_API_KEY, or GOOGLE_API_KEY
from dotenv import load_dotenv
load_dotenv()

# 1. OpenAI (GPT-4)
from langchain_openai import ChatOpenAI
model_openai = ChatOpenAI(model="gpt-4", temperature=0)
result_openai = model_openai.invoke("What is the capital of India?")
print(result_openai.content)

# 2. Anthropic (Claude 3.5)
from langchain_anthropic import ChatAnthropic
model_anthropic = ChatAnthropic(model="claude-3-5-sonnet-20240620")
result_anthropic = model_anthropic.invoke("What is the capital of India?")

# 3. Google (Gemini 1.5 Pro)
from langchain_google_genai import ChatGoogleGenerativeAI
model_google = ChatGoogleGenerativeAI(model="gemini-1.5-pro")
result_google = model_google.invoke("What is the capital of India?")
```

### Open-Source Models
Open-source models (like Llama, Mistral, Falcon) can be downloaded freely from repositories like Hugging Face. 
*   **Advantages:** Zero API costs, complete control, data privacy (since they run locally), and the ability to fine-tune on custom datasets.
*   **Disadvantages:** Requires substantial hardware (expensive GPUs), complex setup processes, and they often lack the extreme refinement of proprietary models.

You can run them via the Hugging Face Inference API or download them locally using the `HuggingFacePipeline`.

```python
# Running a model locally (e.g., TinyLlama)
from langchain_huggingface import ChatHuggingFace, HuggingFacePipeline

# Configure the local LLM pipeline
llm = HuggingFacePipeline.from_model_id(
    model_id="TinyLlama/TinyLlama-1.1B-Chat-v1.0",
    task="text-generation",
    pipeline_kwargs={"max_new_tokens": 100, "temperature": 0.5}
)

model_hf = ChatHuggingFace(llm=llm)
result_hf = model_hf.invoke("What is the capital of India?")
print(result_hf.content)
```

## 2. Embedding Models & Semantic Search
Embedding models do not return text; instead, they take text and return a series of numbers (a vector) that mathematically represents the contextual meaning of that text. This is the foundational technology behind Semantic Search and Retrieval-Augmented Generation (RAG) applications.

Larger dimensional vectors capture more context but cost more to generate and store. You can use proprietary models (like OpenAI's `text-embedding-3-large`) or local open-source models (like `all-MiniLM-L6-v2` via Hugging Face).

### Building a Document Similarity App
To find which document best matches a user's query, you generate vectors for all your documents, generate a vector for the user's query, and calculate the Cosine Similarity between them. 

```python
import numpy as np
from sklearn.metrics.pairwise import cosine_similarity
from langchain_openai import OpenAIEmbeddings
from dotenv import load_dotenv

load_dotenv()

# 1. Initialize Embedding Model
embeddings = OpenAIEmbeddings(model="text-embedding-3-large", dimensions=300)

documents = [
    "Virat Kohli is an Indian cricketer known for his aggressive approach.",
    "MS Dhoni is an Indian cricketer known for his calm demeanor.",
    "Jasprit Bumrah is an Indian fast bowler."
]
query = "Tell me about Bumrah"

# 2. Generate Vectors
doc_embeddings = embeddings.embed_documents(documents)
query_embedding = embeddings.embed_query(query)

# 3. Calculate Cosine Similarity
# cosine_similarity requires 2D lists as inputs
scores = cosine_similarity([query_embedding], doc_embeddings)[0]

# 4. Find the most similar document
indexed_scores = list(enumerate(scores))
sorted_scores = sorted(indexed_scores, key=lambda x: x[1])

best_match_index, highest_score = sorted_scores[-1]

print(f"Query: {query}")
print(f"Best Match: {documents[best_match_index]}")
print(f"Similarity Score: {highest_score}")
```

In a production environment, continuously generating embeddings for static documents is expensive and slow. Instead, you generate the document embeddings once and store them in a Vector Database for quick retrieval later.
