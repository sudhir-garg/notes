# 2. Why LLMs Need Tools

Large language models are excellent at working with language. They can summarize, classify, explain, generate code, and reason over information provided in their context. However, an LLM does not automatically have access to live systems or permission to perform external actions.

For example:

**Question:** "What is the best way to travel from Delhi to Mumbai?"

An LLM can discuss possible options.

**Action:** "Book the train ticket for me."

That requires access to a booking system or API. A tool can provide that
capability.

> An LLM is like a body with a brain and voice, but without hands and legs. It can think and speak, but it cannot act on the outside world by itself.

## What an LLM cannot reliably do by itself
* Fetch live weather, news, prices, or inventory.
* Perform complex calculations with guaranteed accuracy.
* Call external APIs.
* Send email or post messages to collaboration platforms.
* Run Python code or shell commands.
* Query or update a database.
* Trigger bookings, payments, refunds, or business workflows.
* Access private systems unless your app connects them safely.

# 3. What Is a LangChain Tool?

A LangChain tool is usually a Python function wrapped with metadata that an LLM can understand. The wrapper describes the tool’s name, purpose, inputs, and expected structure.

<img width="453" height="65" alt="image" src="https://github.com/user-attachments/assets/df25fc19-6b84-4da6-9b97-9fec62b3b62a" />


A normal function is designed for another programmer to call. A tool is designed so that both a programmer and an LLM can understand how to call it safely and correctly.

## Tool execution flow

<img width="1224" height="1285" alt="image" src="https://github.com/user-attachments/assets/55724228-43eb-4779-a5b0-47075c3c1f8f" />

| Step | Actor | What happens |
| --- | --- | --- |
| 1 | **User** | Describes a goal or asks a question. |
| 2 | **LLM** | Determines whether external information or action is required. |
| 3 | **LLM** | Selects an appropriate tool and prepares structured arguments. |
| 4 | **Tool** | Executes a function, API request, database query, or command. |
| 5 | **Tool** | Returns a result, error, or status. |
| 6 | **LLM** | Interprets the result and produces a user-facing response. |

# 5. Built-In and Custom Tools

<img width="1038" height="298" alt="image" src="https://github.com/user-attachments/assets/40c3bd1d-b55d-489f-a9da-b4c76b2c64d9" />

## When to use built-in tools
Choose a built-in integration when it already matches your requirements. This reduces development time and gives you a familiar interface for common operations.

## When to create a custom tool
Create a custom tool when your application contains domain-specific logic that a general integration cannot provide.

---

# Examples of Built-In Tools

| Tool | Purpose | Example |
| --- | --- | --- |
| **DuckDuckGo Search** | Search the public web. | Find current news or recent information. |
| **Wikipedia query** | Retrieve information from Wikipedia. | Explain a historical or technical topic. |
| **Python REPL** | Execute Python code. | Calculate values or transform data. |
| **Shell tool** | Run shell commands. | Inspect files or system information. |
| **HTTP request tool** | Call web endpoints. | Fetch data from an API. |
| **Gmail or Slack tools** | Interact with communication platforms. | Send an approved notification. |
| **SQL database tools** | Query structured data. | Answer questions using business records. |

## Web search example
```python
from langchain_community.tools import DuckDuckGoSearchRun

search_tool = DuckDuckGoSearchRun()

result = search_tool.invoke("top technology news today")
print(result)
```
The tool sends the query to the search provider and returns results to the application. An agent can then use those results to compose an answer.

## Shell tool example
```python
from langchain_community.tools import ShellTool

shell_tool = ShellTool()

result = shell_tool.invoke({"commands": ["whoami"]})
print(result)
```

# 6. Creating Custom Tools with the `@tool` Decorator

The `@tool` decorator is the simplest way to convert a Python function into a LangChain tool.

<img width="1075" height="187" alt="image" src="https://github.com/user-attachments/assets/49be66dd-75be-421b-b850-63e0edb37674" />


```python
from langchain_core.tools import tool

@tool
def multiply(a: int, b: int) -> int:
    """Multiply two numbers."""
    return a * b

result = multiply.invoke({"a": 3, "b": 5})
print(result)  # 15
```

## Inspecting tool metadata
```python
print(multiply.name)
print(multiply.description)
print(multiply.args)
```

| Metadata | Source | Purpose |
| --- | --- | --- |
| `name` | Usually the function name. | Identifies the tool. |
| `description` | The function docstring. | Explains when and why the LLM should use it. |
| `args` | Function parameters and type hints. | Defines the expected input structure. |

## Why these three matter

An agent needs to know:

``` text
What is this tool?
        ↓
What does it do?
        ↓
What inputs does it require?
```

Good tool metadata therefore improves tool selection and argument
generation.

## The schema is the contract
The LLM does not receive your complete implementation. It receives a structured schema that describes how to call the tool.

```json
{
  "title": "multiply",
  "description": "Multiply two numbers.",
  "type": "object",
  "properties": {
    "a": {
      "title": "A",
      "type": "integer"
    },
    "b": {
      "title": "B",
      "type": "integer"
    }
  },
  "required": ["a", "b"]
}
```

**Writing tip:** Treat the tool name, description, and argument descriptions as part of your prompt design. Clear metadata improves tool selection and reduces malformed calls.

# 7. Structured Tools with Pydantic

Use `StructuredTool` when you need a richer input schema, stronger validation, or clearer descriptions for individual fields.

```python
from pydantic import BaseModel, Field
from langchain_core.tools import StructuredTool

class MultiplyInput(BaseModel):
    a: int = Field(..., description="First number")
    b: int = Field(..., description="Second number")

def multiply_function(a: int, b: int) -> int:
    """Multiply two numbers."""
    return a * b

multiply_tool = StructuredTool.from_function(
    func=multiply_function,
    name="multiply",
    description="Multiply two numbers",
    args_schema=MultiplyInput,
)

print(multiply_tool.invoke({"a": 4, "b": 6}))  # 24
```

**Use this when:** inputs include required and optional fields, constrained values, nested objects, or domain-specific validation.

# 8. Advanced Customization with `BaseTool`

`BaseTool` is the foundational abstraction behind LangChain tools. Extend it when you need direct control over execution behavior, custom error handling, asynchronous execution, or more advanced lifecycle logic.

```python
from typing import Type
from pydantic import BaseModel, Field
from langchain_core.tools import BaseTool

class MultiplyInput(BaseModel):
    a: int = Field(..., description="First number")
    b: int = Field(..., description="Second number")

class MultiplyTool(BaseTool):
    name: str = "multiply"
    description: str = "Multiply two numbers."
    args_schema: Type[BaseModel] = MultiplyInput

    def _run(self, a: int, b: int) -> int:
        return a * b

multiply_tool = MultiplyTool()
print(multiply_tool.invoke({"a": 7, "b": 8}))  # 56
```

# 9. Toolkits: Packaging Related Tools

A toolkit is a reusable collection of related tools. It gives an application a clean way to group capabilities that belong to the same domain.

<img width="1034" height="228" alt="image" src="https://github.com/user-attachments/assets/df2d1337-1934-4711-989d-69f137ac03c7" />

First, define related tools:
```python
from langchain_core.tools import tool

@tool
def add(a: int, b: int) -> int:
    """Add two numbers."""
    return a + b

@tool
def multiply(a: int, b: int) -> int:
    """Multiply two numbers."""
    return a * b
```
Then group them:
```python
class MathToolkit:
    def get_tools(self):
        return [add, multiply]
```
Create the toolkit:
```python
math_toolkit = MathToolkit()

for current_tool in math_toolkit.get_tools():
    print(current_tool.name)
    print(current_tool.description)
```

Toolkits improve reuse, organization, testing, and consistency across multiple agents or applications.

# 11. Key Takeaways

* LLMs can reason and communicate, but tools allow them to act.
* A LangChain tool is commonly a function packaged with a name, description, and input schema.
* Agents combine LLM reasoning, tool execution, and a control loop.
* Built-in tools are useful for common integrations.
* Custom tools are necessary for private APIs, internal systems, and business workflows.
* The `@tool` decorator is the best starting point for most simple tools.
* `StructuredTool` adds explicit schema validation.
* `BaseTool` provides deeper control for advanced applications.
* Toolkits group related capabilities into reusable collections.
* Production tools should validate inputs, minimize permissions, log activity, and protect high-impact actions.

# What Comes Next?

After learning how tools are defined, the next concept is **tool calling**. Tool calling explains how a compatible LLM receives available tool schemas, decides whether a tool is needed, generates structured arguments, and returns a tool call for the application to execute.

**Final perspective:** Tools turn an LLM from a system that only describes actions into a system that can participate in controlled, observable, real-world workflows.
