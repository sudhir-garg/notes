## 1. What Is an LLM Evaluation Method?

An **evaluation method** is the mechanism used to determine whether an LLM output is good, bad, correct, useful, safe, or otherwise meets defined evaluation criteria.

> **Simple mental model:** An evaluation pipeline tells you *what* you want to measure. The evaluation method tells you *who or what executes the judgment*.

**LLM Evaluation Method = Mechanism that takes an output → Produces a judgment or score**

### The Three Core Execution Styles

| Method | Who or What Executes the Evaluation? | Typical Result |
|--------|---------------------------------------|----------------|
| **Programmatic** | Code executes deterministic checks and calculates a metric. | Metric, pass/fail result, validation outcome |
| **Human** | A human evaluator applies judgment, usually using a rubric. | Rating, grade, qualitative feedback |
| **Model-Graded** | An LLM evaluates the output; commonly called **LLM-as-a-Judge**. | Score, label, structured judgment |

### Evaluation Flow

```text
Evaluation Pipeline
(output + criteria)
        │
        ├── Programmatic evaluation ──┐
        ├── Human evaluation ─────────┼──► Judgment / Score
        └── LLM-as-a-Judge ────────────┘    (metric, grade, label, decision)
```

## 2. Programmatic / Deterministic Evaluation

Use this method when correctness can be expressed as a **deterministic rule** or **computable metric**.

### Example: Evaluating a RAG Retriever

**Goal:** Determine whether the retriever returns relevant documents for a query.

| Evaluation Element | Example |
|--------------------|---------|
| **Target** | Retriever component |
| **Task** | Retrieve relevant documents for each query |
| **Success criterion** | Recall@K |
| **Dataset** | 50–100 representative questions with known relevant documents |
| **Execution** | Python / programmatic evaluation |

### Recall@K

Recall@K asks:

> Of all relevant items that exist, how many did the retriever return within its top K results?

**Formula:**

$$
\text{Recall@K}
=
\frac{\text{Number of relevant items retrieved in the top K}}
{\text{Total number of relevant items}}
$$

#### Worked Example

Suppose the relevant documents are:

```text
{1001, 1003}
```

The retriever returns these top-five documents:

```text
{1001, 1002, 1004, 1005, 1006}
```

Only document **1001** was relevant and retrieved.

**Recall@5 = 1 / 2 = 0.5 = 50%**

> **Important:** Recall@K measures coverage of relevant documents. It does not, by itself, tell you whether the returned documents are well-ranked or whether many irrelevant documents were returned. **Precision@K** and **ranking metrics** can complement it.

### Building the Golden Dataset

1. Collect representative user questions.
2. Include easy, difficult, edge-case, and realistic questions.
3. Have a subject-matter expert identify the relevant documents for each question.
4. Store these as the expected or reference labels.

### Programmatic Evaluation Loop

```text
Golden Dataset          Retriever           Python Evaluation        Recall@K
(query + references) ──► (top K documents) ──► (set comparison) ──────► (aggregate)
```

### Python Example

The following function assumes `retrieved_docs` already contains the top K results:

```python
def recall_at_k(relevant_docs, retrieved_docs):
    relevant = set(relevant_docs)
    retrieved = set(retrieved_docs)

    hits = len(relevant & retrieved)

    if not relevant:
        return 0.0

    return hits / len(relevant)


# Example
relevant = {"1001", "1003"}
retrieved_top5 = {"1001", "1002", "1004", "1005", "1006"}

print(recall_at_k(relevant, retrieved_top5))
# 0.5
```

> **Implementation note:** Recall is undefined when there are no relevant items. This example returns `0.0` by convention; define and document how such cases are handled in your benchmark.

### How Do You Improve a Weak Retriever?

- Change or improve the embedding model.
- Perform query expansion or query rewriting.
- Increase `K`.
- Add a reranker.
- Improve chunking, metadata filtering, or retrieval configuration.

## 3. Human-Based Evaluation

Human evaluation is useful when the quality dimension is **subjective**, **nuanced**, or **difficult to encode as deterministic rules**.

### Example: Chatbot Helpfulness

Suppose a Campus X chatbot answers questions about:

- Courses
- Fees
- Certificates
- Refunds
- Eligibility

| Element | Definition |
|---------|------------|
| **Target** | Entire chatbot application |
| **Task** | Evaluate the helpfulness of answers |
| **Possible rubric** | Accuracy + completeness + appropriate tone |
| **Scale** | 1–5 |
| **Execution** | Human evaluator |

### Example Helpfulness Rubric

| Score | Rating | Description |
|-------|--------|-------------|
| **5** | Highly helpful | Accurate, complete, relevant, and appropriately phrased |
| **3** | Partially helpful | Useful, but has meaningful omissions or weaknesses |
| **1** | Not helpful | Incorrect, irrelevant, or fails to address the question |

### Why Use Multiple Human Graders?

If two graders frequently disagree, the disagreement may indicate that the rubric or instructions are ambiguous.

Multiple graders can help:

- Refine the rubric.
- Identify unclear evaluation instructions.
- Measure inter-rater agreement.

> **Important distinction:** Creating a golden dataset with human annotations is different from the execution method used to score an evaluation run. A human may create the reference labels, while the actual evaluation run can still be programmatic or LLM-based.

### Five Common Styles of Human Involvement

| Style | What Humans Do |
|-------|----------------|
| **Direct grading / rating** | Read an output and assign a score using a rubric. |
| **Red teaming** | Deliberately probe a system to discover failures, vulnerabilities, or unsafe behaviors. |
| **A/B testing** | Users interact with different variants and provide feedback or behavioral signals. |
| **Golden dataset / rubric creation** | Experts define expected labels, references, or evaluation criteria. |
| **Human-in-the-loop** | Borderline or complex cases are escalated to a human. |

### Human Evaluation: Trade-Offs

| Strength | Cost / Limitation |
|----------|-------------------|
| Captures nuanced, contextual judgments that are difficult to express as deterministic rules. | Human time is expensive, evaluation can be slow, and scaling is difficult. |
| Uses human expertise and contextual understanding. | Human judgments can vary across evaluators. |

## 4. Model-Graded Evaluation: LLM-as-a-Judge

When deterministic code cannot adequately judge a subjective quality dimension—and large-scale human grading is expensive—an LLM can be used as the evaluator.

**Candidate output → Judge LLM + rubric → Score / label / justification**

### Core Idea

The judge model receives:

- Evaluation context
- Evaluation criteria
- Candidate answer

It then produces a **structured judgment**.

### Inputs to the Judge

| Input | Purpose |
|-------|---------|
| **Question** | What was asked? |
| **Maximum marks / scale** | What is the scoring range? |
| **Rubric** | What dimensions should be checked? |
| **Candidate answer** | What should be evaluated? |
| **Output schema** | Specify a consistent, machine-readable evaluation format. |

### Example Judge Prompt

```python
JUDGE_PROMPT = """
You are grading an answer using the supplied rubric.

Question:
{question}

Maximum marks:
{max_marks}

Rubric:
{rubric}

Candidate answer:
{answer}

For each rubric dimension:
1. Decide whether it is genuinely addressed.
2. Award marks based on the rubric.
3. Do not reward verbosity or keyword stuffing.
4. Do not reward unsupported confident claims.
5. Prefer relevant examples and balanced reasoning.

Return JSON only:
{
  "dimension_scores": [
    {"dimension": "...", "score": 0, "reason": "..."}
  ],
  "total_score": 0,
  "overall_reason": "..."
}
"""
```

> **Implementation note:** If you populate this template using Python's `str.format()`, escape the literal JSON braces as `{{` and `}}`. A prompt alone does not guarantee valid JSON; validate the returned structure or use structured-output support where available.

## 5. LLM-as-a-Judge for Subjective Exam Evaluation

Consider a platform that automatically evaluates **subjective UPSC Mains-style answers**.

The business problem is **scale**: a large number of answers may need expert-style evaluation.

### Step 1 — Define the Target and Success Criterion

| Element | Definition |
|---------|------------|
| **Target** | The answer-evaluation platform |
| **Task** | Evaluate whether the platform scores subjective answers similarly to expert human evaluators |
| **Success criterion** | Agreement between the platform's judgments and expert human judgments |

### Step 2 — Create a Question-Specific Rubric

An expert may define dimensions such as:

1. Addresses ethical governance and accountability.
2. Explains the relationship between them.
3. Provides mechanisms or actionable dimensions.
4. Uses relevant examples.
5. Ends with a balanced conclusion.

> **Rubric ≠ Dataset**
>
> - The **rubric** describes how an answer should be judged.
> - The **dataset** contains actual questions, answers, and human-generated reference evaluations.

### Step 3 — Build a Golden Dataset

| Answer ID | Question | Student Answer | Human Score |
|-----------|----------|----------------|-------------|
| A001 | Question 1 | Actual student answer… | 13 / 15 |
| A002 | Question 1 | Actual student answer… | 4 / 15 |
| A003 | Question 2 | Actual student answer… | 7 / 10 |

The human expert creates the reference score using the same rubric.

A relatively small, carefully curated set can serve as the initial benchmark.

### Step 4 — Run the LLM Judge

```text
Evaluation Inputs
├── Question
├── Maximum marks
├── Rubric
├── Student answer
└── Output schema
        │
        ▼
    Judge LLM
    Checks each rubric dimension
    Assigns scores and justifications
        │
        ▼
    LLM Scores
    Generated for all answers
        │
        ▼
    Comparison
    Human reference scores vs. LLM scores
```

### Step 5 — Compare Human and LLM Scores

For each answer, you now have:

- **Human reference score**
- **LLM judge score**
- **Difference between them**

These differences can be analyzed using a metric such as **Mean Absolute Error**.

## 6. Mean Absolute Error and Judge Agreement

**Mean Absolute Error (MAE)** quantifies the average absolute difference between human reference scores and LLM judge scores.

### Formula

$$
\text{MAE}
=
\frac{1}{N}
\sum_{i=1}^{N}
\left|
\text{Human Score}_i - \text{LLM Score}_i
\right|
$$

Where:

- **N** is the number of evaluated answers.
- **Human Score** is the reference score.
- **LLM Score** is the automated judge's score.

### Example

| Answer | Human Score | LLM Judge Score | Absolute Error |
|--------|-------------|-----------------|----------------|
| 1 | 13 | 12 | 1 |
| 2 | 4 | 8 | 4 |
| 3 | 8 | 8 | 0 |
| 4 | 12 | 10 | 2 |
| 5 | 7 | 6 | 1 |

**MAE = (1 + 4 + 0 + 2 + 1) / 5 = 1.6**

### Python Example

```python
import numpy as np

human = np.array([13, 4, 8, 12, 7])
llm = np.array([12, 8, 8, 10, 6])

mae = np.mean(np.abs(human - llm))

print(f"MAE: {mae:.2f}")
# MAE: 1.60
```

### Interpretation

> A **lower MAE** means the LLM judge's scores are, on average, closer to the human reference scores.
>
> **MAE = 0** means exact score agreement on the evaluated examples.

### Do Not Overinterpret MAE

A low MAE does **not** automatically prove that the judge is correct. It measures agreement with the chosen human reference.

In production, also examine:

- Systematic bias
- Score distributions
- Disagreement cases
- Rubric quality
- Inter-rater agreement
- Performance across different question types

> **Scale matters:** If questions have different maximum marks—for example, 10 and 15—consider reporting MAE separately by scale or normalizing scores before combining them.

### Improving an LLM Judge

- Try a stronger or better-calibrated judge model.
- Improve the rubric and remove ambiguous criteria.
- Improve the judge prompt and output schema.
- Add representative examples where appropriate.
- Analyze high-disagreement cases instead of only looking at the aggregate metric.
- Check whether the judge systematically over-scores or under-scores particular answer styles.

## 7. Reference-Based vs. Reference-Free Evaluation

### Definitions

| Type | Definition |
|------|------------|
| **Reference-Based** | A predefined reference, expected answer, label, document, score, or target is available for each test case. |
| **Reference-Free** | No per-item correct answer is supplied. The output is judged directly against a rubric, criteria, or standard. |

### Examples

| Example | Reference Available? | Type |
|---------|----------------------|------|
| Retriever evaluation with known relevant documents | Yes | Reference-based |
| Chatbot helpfulness graded using a 1–5 rubric without a predefined answer | No | Reference-free |
| Comparing UPSC answer scores against stored human scores | Yes | Reference-based |

### Fast Exam Rule

Ask:

> Does the evaluation dataset contain a predefined correct or reference result for this specific test case?

- **Yes → Reference-based**
- **No → Reference-free**

### Do Not Confuse Rubrics with References

A **rubric** is a scoring standard. A rubric can exist in both reference-based and reference-free evaluation.

What distinguishes reference-based evaluation is the presence of a **predefined per-test-case reference or target**.

> **Case-study distinction:** The LLM judge may grade a student answer without seeing a human reference score. That grading step is reference-free. Comparing its resulting score against the stored human score is reference-based.

## 8. Offline vs. Online Evaluation

The examples above are primarily **offline evaluations**:

1. Start with a fixed evaluation dataset.
2. Run the system against it.
3. Analyze the results before release or during development.

### Comparison

| Aspect | Offline Evaluation | Online Evaluation |
|--------|--------------------|-------------------|
| **Data** | Fixed benchmark or test dataset | Real user interactions and production behavior |
| **Environment** | Development or controlled testing | Production |
| **Primary use** | Repeatable experiments and regression testing | Quality monitoring over time |
| **Timing** | Before release and during iteration | While the system is running |
| **Helps detect** | Regressions and known failure cases | Drift and new failure modes |

### Offline Evaluation

- Uses a fixed benchmark or test dataset.
- Enables repeatable experiments.
- Is useful before release and during iteration.
- Supports regression testing.

### Online Evaluation

- Evaluates a system running in production.
- Uses real user interactions and production behavior.
- Monitors quality over time.
- Helps detect drift and new failure modes.

## 9. Interview / Exam Cheat Sheet

| Question | Answer |
|----------|--------|
| **What is an LLM evaluation method?** | The mechanism used to execute an evaluation and produce a judgment or score. |
| **What are the three core methods?** | Programmatic, human, and model-graded / LLM-graded. |
| **What metric can evaluate a retriever?** | Recall@K is one useful metric; precision and ranking metrics may also be used. |
| **What is the Recall@K formula?** | Relevant items retrieved in the top K ÷ total relevant items. |
| **Why use human evaluation?** | It is useful for nuanced or subjective criteria that are difficult to encode deterministically. |
| **Why not always use humans?** | Cost, time, scalability, and evaluator variability. |
| **What is LLM-as-a-Judge?** | Using an LLM to evaluate another model or system's output against criteria or a rubric. |
| **Why compare an LLM judge with humans?** | To measure how closely the automated judge agrees with expert reference judgments. |
| **What does MAE measure?** | The average absolute difference between two sets of numeric scores. |
| **What does a lower MAE mean?** | Closer average score agreement with the reference scores. |
| **What is reference-based evaluation?** | Evaluation with a predefined per-test-case reference or target. |
| **What is reference-free evaluation?** | Evaluation without a predefined per-test-case answer; the output is judged directly against criteria or a rubric. |
| **What is a golden dataset?** | A curated evaluation dataset with trusted human or reference annotations or labels. |
| **Is golden dataset creation the same as the evaluation execution method?** | No. Human annotation may create the references, while execution can later be programmatic or model-graded. |

### One-Picture Mental Model

```text
Evaluation Dataset
(questions + optional references)
        │
        ▼
Application
(LLM / RAG / Agent)
        │
        ▼
Candidate Outputs + Evaluation Criteria
        │
        ├── Program ──────── Deterministic checks ──┐
        ├── Human ───────── Rubric / judgment ─────┼──► Metric / Judgment
        └── LLM Judge ───── Model-based judgment ──┘
```

> **Production mindset:** Building an LLM application is only part of the engineering problem. A production-grade system also needs a repeatable way to determine whether its behavior meets the intended quality criteria.
