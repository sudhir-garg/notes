## 1. What is FastAPI?

FastAPI is a modern Python web framework built for APIs. It supports both synchronous and asynchronous route handlers.

### Key idea
You can write:
- `def` for sync endpoints
- `async def` for async endpoints

FastAPI handles both, but async is especially powerful for I/O-heavy applications.

---

## 2. Why FastAPI is Popular for Async Work

FastAPI is popular because it:
- supports `async` naturally
- works with ASGI servers like Uvicorn
- helps handle many requests efficiently
- fits well with async database and HTTP libraries
- reduces blocking when used correctly

### Why this matters
If your app spends time waiting on:
- databases
- APIs
- file/network operations

then async can help your server stay responsive and handle more users.

---

## 3. What is Async I/O?

Async I/O is a programming style where code does not block while waiting for slow operations.

### Simple idea
Instead of:
1. start request
2. wait
3. continue

Async I/O allows:
1. start request
2. pause that task
3. do other work
4. resume when ready

### Good for
- network calls
- database queries
- file reads/writes
- message queues
- WebSocket communication

### Not mainly for
- heavy CPU calculations
- image processing
- large in-memory loops

---

## 4. The Event Loop

The **event loop** is the core of async execution.

### Think of it like a coordinator
It:
- tracks waiting tasks
- switches to other ready tasks
- resumes paused tasks when their I/O finishes

### Why it matters in FastAPI
When one request is waiting on I/O, the event loop can serve other requests instead of sitting idle.

## 5. async def and await

### `async def`
Defines an asynchronous function.

```python
async def fetch_data():
    ...
```

### `await`
Tells Python to pause here until the awaited operation is done.

```python
data = await fetch_data()
```

### Example
```python
from fastapi import FastAPI
import asyncio

app = FastAPI()

@app.get("/slow")
async def slow_endpoint():
    await asyncio.sleep(2)
    return {"message": "done"}
```

Here, `await asyncio.sleep(2)` does not block the whole server.

## 6. Sync vs Async in FastAPI

FastAPI supports both styles.

### Sync
```python
from fastapi import FastAPI

app = FastAPI()

@app.get("/sync")
def sync_endpoint():
    return {"message": "sync"}
```

### Async
```python
from fastapi import FastAPI

app = FastAPI()

@app.get("/async")
async def async_endpoint():
    return {"message": "async"}
```

### When to choose which
- Use **sync** for simple logic or blocking libraries
- Use **async** for I/O-heavy tasks with async libraries

---

## 7. Blocking vs Non-Blocking Code

### Blocking code
Blocks the thread while waiting.

Examples:
- `time.sleep()`
- `requests.get()`
- sync DB drivers
- sync file/network libraries

### Non-blocking code
Allows the event loop to do other work.

Examples:
- `await asyncio.sleep()`
- `httpx.AsyncClient`
- `asyncpg`
- async Redis clients

---

## 8. Common Mistake: Blocking Code Inside async def

A major mistake is mixing async syntax with blocking libraries.

### Bad example
```python
from fastapi import FastAPI
import time

app = FastAPI()

@app.get("/bad")
async def bad_endpoint():
    time.sleep(5)
    return {"message": "done"}
```

### Why this is bad
Even though the function is async, `time.sleep()` blocks the event loop. That prevents the server from handling other requests efficiently.

### Better example
```python
from fastapi import FastAPI
import asyncio

app = FastAPI()

@app.get("/good")
async def good_endpoint():
    await asyncio.sleep(5)
    return {"message": "done"}
```

## 9. How to Know What is Async-Compatible

A simple rule:

> If a library explicitly offers async support, use that version.

### Look for these signs
- `AsyncClient`
- `AsyncSession`
- `async def` in docs
- `await` in examples

### Common examples

| Library / operation | Async-compatible? | Notes |
|---|---|---|
| `httpx.AsyncClient` | Yes | Async HTTP |
| `requests` | No | Blocking HTTP |
| `asyncpg` | Yes | Async PostgreSQL |
| `psycopg2` | No | Blocking PostgreSQL |
| `time.sleep()` | No | Always blocks |
| `asyncio.sleep()` | Yes | Non-blocking pause |

### Practical test
If a function:
- waits on network/disk/database
- and there is no async API
then it is probably blocking.

## 10. How to Convert Sync Code to Async Style

You cannot make code truly async by renaming `def` to `async def`. You must also replace blocking calls.

### Step 1: Identify blocking operations
Examples:
- `time.sleep()`
- `requests`
- sync DB client
- sync SDKs

### Step 2: Replace with async alternatives
- `time.sleep()` → `await asyncio.sleep()`
- `requests` → `httpx.AsyncClient`
- sync DB driver → async DB driver

### Step 3: Use `await`
If the function returns a coroutine, await it.

### Example
#### Sync
```python
import requests

def fetch_data():
    response = requests.get("https://api.example.com/data")
    return response.json()
```

#### Async
```python
import httpx

async def fetch_data():
    async with httpx.AsyncClient() as client:
        response = await client.get("https://api.example.com/data")
    return response.json()
```

## 11. Using Threads for Sync Functions

If you must use a sync function inside async code, you can offload it to a thread so it does not block the event loop.

### Why this helps
The function is still sync, but it runs in a separate thread. That means the async event loop can keep handling other requests.

### Example using `asyncio.to_thread()`

```python
from fastapi import FastAPI
import asyncio
import time

app = FastAPI()

def blocking_task():
    time.sleep(3)
    return "blocking work done"

@app.get("/threaded")
async def threaded_endpoint():
    result = await asyncio.to_thread(blocking_task)
    return {"message": result}
```

### Explanation
- `blocking_task()` is a normal sync function
- `asyncio.to_thread()` runs it in a background thread
- `await` waits for the result without blocking the event loop

### When to use this
Use threads when:
- you have a blocking library and no async alternative
- the task is I/O-bound, not CPU-heavy
- you want to keep your async endpoint responsive

### When not to use this
Do **not** rely on threads for very CPU-heavy work. For CPU-heavy work, use:
- a process pool
- background workers
- task queues like Celery/RQ

## 12. FastAPI App with Sync and Async Endpoints

FastAPI apps can mix both styles.

```python
from fastapi import FastAPI
import time
import asyncio

app = FastAPI()

@app.get("/sync")
def sync_endpoint():
    time.sleep(1)
    return {"message": "This is a sync endpoint"}

@app.get("/async")
async def async_endpoint():
    await asyncio.sleep(1)
    return {"message": "This is an async endpoint"}

def calculate_sum(a: int, b: int) -> int:
    return a + b

@app.get("/mix")
async def mixed_endpoint(a: int = 1, b: int = 2):
    result = calculate_sum(a, b)
    await asyncio.sleep(0.5)
    return {"sum": result, "message": "Mixed sync + async"}
```

### Explanation
- `sync_endpoint()` is normal blocking-style Python
- `async_endpoint()` uses async sleep and does not block
- `mixed_endpoint()` shows that small sync helpers can still be called from async code

## 13. Async Database Access Example

This is the kind of case where async is very useful.

```python
from fastapi import FastAPI, Depends
from sqlalchemy.ext.asyncio import AsyncSession, create_async_engine, async_sessionmaker
from sqlalchemy import text

DATABASE_URL = "postgresql+asyncpg://user:password@localhost:5432/mydb"

engine = create_async_engine(DATABASE_URL, echo=True)
AsyncSessionLocal = async_sessionmaker(engine, class_=AsyncSession, expire_on_commit=False)

app = FastAPI()

async def get_db():
    async with AsyncSessionLocal() as session:
        yield session

@app.get("/items")
async def get_items(db: AsyncSession = Depends(get_db)):
    result = await db.execute(text("SELECT id, name FROM items"))
    rows = result.mappings().all()
    return {"items": rows}
```

### Why this is async
- async SQLAlchemy engine
- async session
- `await db.execute(...)`

## 14. Async HTTP Request Example

```python
from fastapi import FastAPI
import httpx

app = FastAPI()

@app.get("/external")
async def call_external_api():
    async with httpx.AsyncClient() as client:
        response = await client.get("https://api.example.com/data")
    return response.json()
```

### Why this is better than `requests`
`requests` blocks. `httpx.AsyncClient` yields control while waiting.

## 15. When to Use Sync vs Async

| Use case | Prefer sync `def` | Prefer async `async def` |
|---|---|---|
| Simple logic | Yes | No need |
| Pure calculations | Yes | No benefit |
| Blocking libraries | Yes | Only if wrapped carefully |
| Async DB driver | No | Yes |
| HTTP API calls | No | Yes |
| File/network waiting | No | Yes |
| CPU-heavy work | Yes | Usually no |
| WebSocket/streaming | No | Yes |

### Rule of thumb
- Use sync when the code is simple or blocking anyway
- Use async when the code spends time waiting on I/O and async libraries are available

---

## 16. Best Practices

- Use `async def` only when you benefit from async I/O
- Use async-compatible libraries inside async routes
- Avoid `time.sleep()` in async code
- Avoid `requests` in async code
- Use sync endpoints when your library stack is sync-only
- Prefer async DB/HTTP clients when building high-concurrency APIs
- Keep long CPU-heavy tasks out of request handlers
- Use `asyncio.to_thread()` when you must call sync I/O code from async routes

---

## 17. Summary

FastAPI supports both sync and async code, but async is especially useful for I/O-heavy workloads.

### Key ideas
- `async def` lets FastAPI handle waiting operations efficiently
- `await` pauses only the current task, not the whole server
- blocking code inside `async def` defeats the purpose
- async libraries are required for true non-blocking behavior
- threads can help when you must call sync code from an async route

### Final takeaway
Use sync functions for simple or blocking work, and use async functions when your app waits on network, database, or other I/O operations. If you have blocking sync code that must be used in an async route, offload it with `asyncio.to_thread()`.
