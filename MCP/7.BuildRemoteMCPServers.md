## Introduction: Local vs. Remote MCP Servers

MCP servers generally fall into two categories: **local** and **remote**.

### Local MCP Servers

Local MCP servers run on the **same machine** as the MCP client, such as Claude Desktop.

#### Advantages

- very fast communication
- no network latency
- simple development workflow

#### Limitations

- limited by your local machine’s compute power
- generally serve only one user or one desktop environment at a time

### Remote MCP Servers

Remote MCP servers run on **external machines or cloud servers** and communicate with clients over the internet.

#### Advantages

- can serve multiple clients simultaneously
- can use more powerful remote hardware
- are better suited for enterprise and shared deployments

#### Limitations

- slower than local servers because of network latency
- require deployment, hosting, and connectivity setup

## Setting Up a Simple Remote Server

Building a remote MCP server is almost identical to building a local one. The major difference is the **transport layer**:

- **Local server:** usually uses `STDIO`
- **Remote server:** uses `HTTP`

### Step-by-Step Initialization

Use the following commands to initialize the project:

```bash
# 1. Install uv
pip install uv

# 2. Create a new project directory
mkdir test-remote-server
cd test-remote-server

# 3. Initialize the project
uv init .

# 4. Install FastMCP
uv add fastmcp
```

### Example Code: Basic Remote Server

Create a file named `main.py`:

```python
from fastmcp import FastMCP
import random

# Initialize the MCP Server
mcp = FastMCP("Simple Calculator Server")

@mcp.tool()
def add_numbers(a: int, b: int) -> int:
    """Add two numbers together."""
    return a + b

@mcp.tool()
def generate_random_number(min_val: int, max_val: int) -> int:
    """Generate a random number between a minimum and maximum value."""
    return random.randint(min_val, max_val)

# A resource providing server info
@mcp.resource("server://info")
def get_server_info() -> str:
    return "This is a simple test remote MCP server."
```

### Running the Remote Server Locally

To run the server locally over HTTP:

```bash
uv run fastmcp run main.py --transport http --host 0.0.0.0 --port 8000
```

> **Note:** You can also test this with the MCP Inspector by running:
>
> ```bash
> uv run fastmcp dev main.py
> ```
>
> Then select **SSE/HTTP** as the transport type.

## Deploying the Remote Server via FastMCP Cloud

To make your server publicly accessible, deploy it using **FastMCP Cloud**.

### Deployment Steps

1. Initialize Git in your project folder.
2. Commit your code (`main.py`).
3. Push the project to a new GitHub repository.
4. Open **fastmcp.cloud**.
5. Link your GitHub account.
6. Select the repository.
7. Set `main.py` as the entry point.
8. Click **Deploy**.

### Result

FastMCP Cloud will generate a **public URL** for your deployed remote MCP server.

## Connecting the Remote Server to Claude Desktop (Pro Users)

If you are using the **Claude Pro** plan, Claude Desktop supports remote connectors natively.

### Steps

1. Open **Claude Desktop**
2. Go to **Settings**
3. Open **Connectors**
4. Click **Add Custom Connector**
5. Provide:
   - a connector name
   - the FastMCP Cloud URL

### Example

You might add a connector named:

> `Nitish Test MCP Server`

Once connected, you can prompt Claude with:

> “Generate random number between 11 and 20.”

Claude will call the deployed remote MCP server and return the response.

### Issue 1: SQLite Read-Only Error

#### Problem

When deployed in the cloud environment, adding an expense failed with a:

> “database is set to read-only mode”

error.

#### Cause

Hosted environments may not always provide write permissions in the same way as a local development machine.

#### Solution

Update the database initialization logic to ensure:

- the directory is writable
- the database file is created with proper write permissions
- the hosted runtime can persist changes correctly

---

### Issue 2: Synchronous Blocking Operations

#### Problem

Using Python’s standard `sqlite3` library means database operations are synchronous.

In a remote server scenario, if multiple users make requests at the same time, those requests may block each other and create a bottleneck.

#### Solution

Convert the server to an **asynchronous implementation** using:

- `aiosqlite`
- `async def`
- `await`

This allows multiple concurrent users to interact with the server more efficiently.

### Example Code: Asynchronous Expense Tracker

First, install `aiosqlite`:

```bash
uv add aiosqlite
```

Then update the tool implementation:

```python
import aiosqlite
from fastmcp import FastMCP

mcp = FastMCP("Remote Expense Tracker")
DB_PATH = "expenses.db"

@mcp.tool()
async def add_expense(date: str, amount: float, category: str, note: str) -> str:
    """Add a new expense entry asynchronously."""
    async with aiosqlite.connect(DB_PATH) as conn:
        await conn.execute(
            "INSERT INTO expenses (date, amount, category, note) VALUES (?, ?, ?, ?)",
            (date, amount, category, note)
        )
        await conn.commit()
    return "Expense added successfully."
```

### Example Prompt

> “Add an expense online course subscription last Saturday 500.”

This asynchronous approach helps prevent performance issues when multiple users access the remote server at the same time.

## Workaround: Connecting Remote Servers for Free Claude Users (Proxy Server)

Free Claude Desktop users may not have access to the **Add Custom Connector** UI.

A workaround is to use **FastMCP’s local proxy server**.

### How It Works

The proxy runs locally and acts as a middle layer:

- Claude Desktop connects to the **local proxy** using standard `STDIO`
- the proxy forwards requests to your **remote FastMCP Cloud server** over the internet

This allows remote server access even without native custom connector support.

### Example Code: Proxy Server

Create a file named `proxy.py`:

```python
from fastmcp import FastMCP

# Insert your deployed FastMCP Cloud URL here
REMOTE_URL = "https://your-deployed-server-url.fastmcp.cloud"

# Create a proxy server
proxy = FastMCP.as_proxy(REMOTE_URL)
proxy.name = "Nitish Server Proxy"

if __name__ == "__main__":
    # Runs locally on STDIO transport
    proxy.run()
```

### Installing the Proxy in Claude Desktop

Install the proxy with:

```bash
uv run fastmcp install claude-desktop proxy.py
```

> **Note:** If you encounter startup errors, make sure the absolute path to `uv` is correctly configured in `claude_desktop_config.json`.

## The Ultimate Flaw: Lack of Multi-Tenant Architecture and Authentication

Although the remote server works technically, it introduces a major architectural problem when multiple users share the same deployment.

### The Problem

The SQLite database stores all expenses in one centralized table without any user isolation.

That means:

- if **User A** adds an expense
- and **User B** asks to list all September expenses

then **User B may see User A’s financial data**

### Why Adding `user_id` Alone Is Not Enough

Even if you add a `user_id` column, the server still needs a reliable way to know:

- who the current user is
- whether that user is authenticated
- whether that user is authorized to access specific rows

Without authentication, there is no trustworthy identity boundary.

### Why This Matters

For any real-world or enterprise-grade MCP deployment, you need:

- authentication
- session handling
- user-level access control
- tenant isolation

Without these, the system is not safe for multi-user production use.
