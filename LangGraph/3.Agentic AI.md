## What is Agentic AI?

Agentic AI is a type of artificial intelligence that takes a high-level task or goal from a user and works autonomously to complete it with minimal human guidance. It independently plans, takes action, adapts to changes, and seeks human help only when necessary.

| Feature | Generative AI (e.g., ChatGPT) | Agentic AI |
| :--- | :--- | :--- |
| **Operation Mode** | Reactive | Proactive and Autonomous |
| **Workflow** | Requires step-by-step prompting for each sub-task. | Requires a single high-level goal; handles all sub-tasks itself. |
| **Example (Travel)** | You ask for flight dates, then separately ask for hotels, then separately ask for an itinerary. | You state your travel dates/destination; the AI independently finds flights, books hotels, and creates the itinerary. |

## Real-World Example: The AI HR Recruiter

To understand how Agentic AI operates, consider an AI agent tasked with hiring a Backend Engineer. The workflow happens completely autonomously:

*   **Goal Ingestion:** The human HR provides constraints (e.g., remote, 2-4 years of experience).
*   **Planning:** The agent devises a step-by-step plan: draft a Job Description (JD), post it, monitor applications, screen resumes, schedule interviews, and roll out offers.
*   **Execution & Tool Usage:** The agent accesses internal company documents to draft the JD, uses APIs (like LinkedIn) to post it, and uses a resume parser to evaluate applicants.
*   **Adaptation:** If only two people apply within a few days, the agent proactively suggests running LinkedIn ads or changing the JD to "Full-Stack Engineer" to attract more candidates.
*   **Context & Scheduling:** It checks the human HR’s calendar API, finds an open slot, and autonomously emails the candidate to schedule the interview.
*   **Onboarding:** Once a candidate is selected, it drafts the offer letter, tracks acceptance, and triggers IT provisioning for a new laptop.

## 6 Key Characteristics of Agentic AI

**1. Autonomy**
The system makes decisions and takes actions without step-by-step human instructions. Because unchecked autonomy can be dangerous, it must be controlled via:
*   **Scope limits:** Restricting which tools the agent can use.
*   **Human-in-the-loop (HITL):** Requiring human approval before executing high-risk steps.
*   **Override controls:** Allowing the user to pause or alter behavior mid-task.
*   **Guardrails:** Setting strict ethical boundaries.

**2. Goal-Oriented**
The agent operates with a persistent objective. Goals act as a compass for the agent's autonomy and can include specific constraints.

```json
{
  "main_goal": "Hire a Backend Engineer",
  "constraints": {
    "experience_years": "2-4",
    "remote": true,
    "tech_stack": ["Python", "Django", "AWS"]
  },
  "status": "Active"
}
```

**3. Planning**
Agentic systems operate in a continuous loop of planning and execution. The planning phase involves breaking down a high-level goal into a structured sequence of actions by generating, evaluating, and selecting optimal plans.

**4. Reasoning**
The cognitive process through which the agent interprets information, draws conclusions, and makes decisions. Reasoning is required during planning (to decompose goals) and execution (to handle errors or evaluate alternatives).

**5. Adaptability**
The ability to modify plans, strategies, or actions in response to unexpected conditions, such as API failures or negative external feedback.

**6. Context Awareness**
The agent understands, retains, and utilizes relevant information across multi-step, multi-day processes utilizing both short-term (session state) and long-term (guardrails, preferences) memory.

---

## 5 Core Components of an Agentic AI System

*   **Brain (LLM):** The core intelligence engine that handles reasoning, goal interpretation, planning, tool selection, and natural language communication.
*   **Orchestrator:** The framework (e.g., LangGraph, CrewAI) that sequences tasks, handles conditional routing, manages retry logic, and acts as the project manager for execution.
*   **Tools:** The external APIs, databases, or RAG (Retrieval-Augmented Generation) knowledge bases that allow the agent to interact with the outside world.
*   **Memory:** The storage system keeping track of both short-term session states and long-term user preferences and goals.
*   **Supervisor:** The component responsible for enforcing guardrails, managing edge cases, and handling Human-in-the-Loop approvals before high-risk actions are executed.

## Building an Agentic System: LangGraph Code Example

This working example builds a miniature version of the AI HR Recruiter using LangGraph.

```python
import os
from typing import Annotated
from typing_extensions import TypedDict
from langchain_openai import ChatOpenAI
from langchain_core.tools import tool
from langgraph.graph import StateGraph, START, END
from langgraph.graph.message import add_messages
from langgraph.prebuilt import ToolNode, tools_condition
from langgraph.checkpoint.memory import MemorySaver

# 1. TOOLS
@tool
def search_resumes(skill: str) -> str:
    """Searches the database for candidates matching a specific skill."""
    print(f"\n[Tool Execution] Searching database for '{skill}'...")
    if skill.lower() in ["python", "backend"]:
        return "Found 2 candidates: Alice (3 yrs Python), Bob (1 yr Python)."
    return "No candidates found for that skill."

@tool
def schedule_interview(candidate_name: str) -> str:
    """Schedules an interview with the specified candidate."""
    print(f"\n[Tool Execution] Accessing calendar to schedule {candidate_name}...")
    return f"Success: Interview scheduled with {candidate_name} for Friday at 2 PM."

tools = [search_resumes, schedule_interview]

# 2. BRAIN
llm = ChatOpenAI(model="gpt-4o", temperature=0)
llm_with_tools = llm.bind_tools(tools)

class State(TypedDict):
    messages: Annotated[list, add_messages]

# 3. ORCHESTRATOR
graph_builder = StateGraph(State)

def chatbot(state: State):
    return {"messages": [llm_with_tools.invoke(state["messages"])]}

graph_builder.add_node("chatbot", chatbot)
tool_node = ToolNode(tools=[search_resumes, schedule_interview])
graph_builder.add_node("tools", tool_node)

graph_builder.add_conditional_edges("chatbot", tools_condition)
graph_builder.add_edge("tools", "chatbot")
graph_builder.add_edge(START, "chatbot")

# 4. MEMORY
memory = MemorySaver()

# 5. SUPERVISOR / HUMAN-IN-THE-LOOP
# Remove interrupt_before=["tools"] for full autonomy
graph = graph_builder.compile(
    checkpointer=memory,
    interrupt_before=["tools"] 
)

def run_agent():
    config = {"configurable": {"thread_id": "hr_hiring_session_1"}}
    user_input = "I need to hire a Python backend engineer. Can you find someone and schedule them?"
    print(f"Human: {user_input}")
    
    events = graph.stream({"messages": [("user", user_input)]}, config, stream_mode="values")
    for event in events:
        if "messages" in event:
            last_msg = event["messages"][-1]
            if last_msg.type == "ai" and not last_msg.tool_calls:
                print(f"Agent: {last_msg.content}")

    snapshot = graph.get_state(config)
    if snapshot.next:
        print("\n[Supervisor Alert] The agent wants to use a tool. Type 'yes' to approve.")
        user_approval = input("Approve? (yes/no): ")
        
        if user_approval.lower() == 'yes':
            events = graph.stream(None, config, stream_mode="values")
            for event in events:
                if "messages" in event:
                    last_msg = event["messages"][-1]
                    if last_msg.type == "ai" and not last_msg.tool_calls:
                        print(f"Agent: {last_msg.content}")
        else:
            print("Action blocked by supervisor.")

if __name__ == "__main__":
    run_agent()
```

## How Autonomy Works Under the Hood

When the supervisor pause (`interrupt_before=["tools"]`) is removed, the system achieves full autonomy through a cyclic **Reasoning and Acting (ReAct) loop**. 

1. **First Thought:** The LLM receives the goal. It reasons it must find candidates first and requests the `search_resumes` tool.
2. **First Action:** The Orchestrator routes the request to the `tools` node, executes the Python function, and captures the result ("Alice and Bob").
3. **The Autonomous Pivot:** The Orchestrator routes the result back to the Brain. The LLM reads the result and reasons it still needs to fulfill the scheduling portion of the goal.
4. **Second Action:** The LLM generates a command to trigger the `schedule_interview` tool for Alice.
5. **Goal Completion:** The scheduling success message is fed back to the LLM. The LLM determines the goal is satisfied, breaks the loop, and outputs a final English response.

---

## Adaptability and Error Recovery

When a tool fails, the orchestrator prevents a system crash by capturing the error and sending it back to the LLM as an observation.

1. **The Attempt:** The agent calls a tool (e.g., `schedule_interview(date="Sunday")`).
2. **The Failure:** The tool returns an error string (e.g., `"Error: Cannot schedule on weekends."`).
3. **The Feedback:** The orchestrator routes the error text back to the LLM.
4. **The Pivot:** The LLM reads the error, adapts its plan, and calls the tool with corrected parameters (`schedule_interview(date="Monday")`) or tries a fallback approach.

To prevent infinite loops during total API outages, orchestrators implement a **Max Recursion Limit**. If the agent loops too many times, the framework gracefully halts execution and escalates the issue to the human user.

## Agentic AI State Graph

```text
            ( START )
                │
                ▼
       ┌─────────────────┐
 ┌────►│    chatbot      │──────┐
 │     └─────────────────┘      │
 │       │               │      │
 │       │ Tool Call     │      │ No Tool Call
 │       │               │      │ (Goal complete)
 │       ▼               │      │
 │  ┌───────────────┐    │      ▼
 └──│     tools     │    │   ( END )
    └───────────────┘    │
      (Tool Results)     │
```

| Component | Type | Description |
| :--- | :--- | :--- |
| **`START`** | Entry Point | Injects the user's initial goal into the state and passes it to the `chatbot` node. |
| **`chatbot`** | Node | The LLM acts as the Brain. It evaluates the current state and decides the next action. |
| **`tools_condition`** | Conditional Edge | The router. If the LLM generates a tool call, it routes to `tools`. If it outputs a standard text response, it routes to `END`. |
| **`tools`** | Node | The execution environment. It runs the requested Python functions and passes the raw output back to the state. |
| **Feedback Loop** | Standard Edge | The edge pointing from `tools` back to `chatbot`. This creates the ReAct loop, ensuring the agent evaluates its actions. |
| **`END`** | Exit Point | Terminates graph execution when the LLM determines the goal is fully achieved. |
