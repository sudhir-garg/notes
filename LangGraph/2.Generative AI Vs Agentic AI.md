## Understanding Generative AI

Generative AI refers to a class of AI models that can create new content—such as text, images, audio, code, or video—that closely resembles human-created data. 

**Popular Modalities & Examples:**
*   **Text:** ChatGPT, Gemini, Claude, Grok (mimicking human writing and reasoning).
*   **Images:** DALL-E, Midjourney (generating images from text descriptions).
*   **Code:** Code Llama (auto-completing and debugging software code).
*   **Audio:** ElevenLabs (Text-to-Speech models sounding like real humans).
*   **Video:** Sora, Runway (generating video clips from text prompts).

---

## Traditional AI vs. Generative AI

| Feature | Traditional AI (Classical ML/Deep Learning) | Generative AI |
| :--- | :--- | :--- |
| **Core Function** | Finds patterns and mathematical relationships between input and output. | Learns the underlying distribution (nature/behavior) of the data. |
| **Primary Use Cases** | Classification (e.g., spam detection) and Regression (e.g., stock price prediction). | Content Creation (creating a new sample, like generating a fake image of a cat). |
| **Output Type** | Predictions, labels, or continuous numbers. | New text, images, code, or audio. |

## The Evolution of AI: A Practical HR Scenario

To understand the difference between Gen AI and Agentic AI, consider an HR Recruiter tasked with hiring a Backend Engineer (2-4 years experience). The process requires drafting a Job Description (JD), posting it, shortlisting resumes, scheduling interviews, and onboarding. 

Here is how different levels of AI handle this exact same task, along with architectural code examples:

### Level 1: Basic Generative AI Chatbot
You chat with a standard LLM. 
*   **Capabilities:** It can draft a generic JD, suggest generic interview questions, and write template emails.
*   **Limitations:** It is purely **reactive** (you must prompt it for every single step), lacks memory, gives generic advice not tailored to your company, and cannot take external actions.

```python
from langchain_openai import ChatOpenAI

llm = ChatOpenAI(model="gpt-4")

# Reactive: The human asks for a generic JD
response = llm.invoke("Draft a Job Description for a Backend Engineer with 2-4 years of experience.")

print(response.content)
```

### Level 2: RAG-Based Chatbot (Retrieval-Augmented Generation)
The chatbot is connected to your company’s internal knowledge base (past JDs, salary bands, hiring playbooks).
*   **Capabilities:** It generates highly specific, tailored JDs based on your company's tech stack and past successful hires. 
*   **Limitations:** It provides tailored advice, but remains reactive and still cannot execute tasks outside the chat window.

```python
from langchain_openai import ChatOpenAI
from langchain.chains import create_retrieval_chain
from langchain.chains.combine_documents import create_stuff_documents_chain

llm = ChatOpenAI(model="gpt-4")
```

### Level 3: Tool-Augmented Chatbot
The chatbot is integrated with external APIs (LinkedIn, Naukri, Resume Parsers, Calendar).
*   **Capabilities:** When prompted, it can post the JD directly to LinkedIn, download resumes, and check your calendar.
*   **Limitations:** While it executes actions, it lacks **adaptability**. It cannot independently realize that applications are low and strategize a fix. The human is still the project manager.

```python
    return "Job successfully posted to LinkedIn."

# 2. Bind the tool to the LLM
```

### Level 4: Agentic AI
You give the system a single goal: *"Hire a Backend Engineer."*
*   **Capabilities:** The AI acts as an autonomous agent. It understands the goal, plans the steps, and executes them proactively. It **continuously monitors** progress. If only two people apply, the AI identifies the problem, formulates a solution (e.g., "Should we broaden the JD to Full Stack?"), asks for your approval, and adapts its strategy.

```python
from langgraph.graph import StateGraph, END
from typing import TypedDict, List

# Define the state the agent keeps track of
class HiringState(TypedDict):
    goal: str
    current_step: str
    applications_received: int

# Initialize the LangGraph StateGraph
workflow = StateGraph(HiringState)

# 1. Add Nodes (The autonomous actions the agent can take)
workflow.add_node("draft_and_post", draft_and_post_job)
workflow.add_node("monitor_job", check_linkedin_api_for_applicants)
workflow.add_node("replan_strategy", adapt_job_description) 
workflow.add_node("shortlist_and_schedule", screen_resumes_and_email)

# 2. Add Conditional Routing (Proactivity & Adaptability)
def routing_logic(state: HiringState):
    if state["applications_received"] > 10:
        return "sufficient_candidates"
    else:
        return "low_candidates"

workflow.add_conditional_edges(
    "monitor_job",
    routing_logic,
    {
        "low_candidates": "replan_strategy", # Agent realizes a problem and adapts
        "sufficient_candidates": "shortlist_and_schedule"
    }
)

# 3. Compile and Run the Agent
agent = workflow.compile()

# You just provide the end goal. The agent loops through the graph autonomously.
agent.invoke({"goal": "Hire a Backend Engineer with 2-4 years experience"})
```

## Key Differences: Gen AI vs. Agentic AI

*   **Goal Orientation:** Generative AI focuses entirely on *creating content*. Agentic AI focuses on *achieving a specific goal* through planning and step-by-step execution.
*   **Proactivity:** Generative AI is strictly reactive (waiting for human prompts). Agentic AI is proactive and autonomous, requiring human input mostly for final approvals.
*   **The Relationship:** Generative AI is a *capability*, while Agentic AI is a *behavior*. Agentic systems use Generative AI (LLMs) as their core reasoning engine to plan, use tools, and manage memory.
