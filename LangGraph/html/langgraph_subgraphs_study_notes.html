1. Overview

In LangGraph, a subgraph is a graph used as a component inside a larger, parent graph. Instead of putting every operation into one enormous workflow, you can package a coherent piece of work—such as translation, coding, testing, or review—into its own graph.

Core idea: a node usually performs a task; a subgraph lets a whole sequence of tasks act as one component in a larger workflow.

These notes follow the supplied lesson’s structure: conceptual definition, motivation, benefits, and the two ways of connecting a subgraph to a parent graph. Code below is a compact teaching example; check the LangGraph version and model-provider package in your environment before running it.

2. What is a subgraph?

A graph represents a workflow as nodes connected by edges. A node may call an LLM, retrieve documents, call a tool, validate an answer, or perform another task. A subgraph is a smaller graph that is incorporated into a parent graph.

Diagram: the parent graph sees the translation subgraph as one workflow component, even though the subgraph contains its own internal steps.

Example: a parent workflow might generate an English answer and then invoke a translation subgraph that returns a Hindi translation.

3. Why are subgraphs useful?

Real-world GenAI applications often grow beyond a single prompt and response. A workflow may need tools, retrieval-augmented generation (RAG), conditional routing, retries, memory, human review, evaluation, and guardrails.

Rather than build one tangled graph, split the system into smaller, focused subgraphs. A coding subgraph can contain coding-specific prompts, tools, checks, and retry logic; a testing subgraph can contain test execution and result interpretation.

4. Benefits and design considerations

Modularity

Separate responsibilities into understandable units. Each graph has a clear purpose and boundary.

Reusability

Reuse a coding or translation subgraph in more than one workflow, when its inputs and outputs fit.

Maintainability

Debug or update a focused unit without needing to understand every unrelated part of the overall graph.

State boundaries

Choose whether the child graph uses its own schema or works directly with the parent’s shared state schema.

Observability

Graph and subgraph execution can be inspected/traced at useful levels, depending on the tracing setup and configuration.

Failure handling

Smaller components make errors easier to locate. Explicit retries, fallbacks, and exception handling are still needed where appropriate.

Important nuance: a subgraph boundary is not, by itself, a guarantee that failures are isolated or that the rest of a workflow always continues. Define error handling and fallback behavior deliberately.

6. Example A — invoke a translation subgraph from a node

In this pattern, the child graph uses a small state schema containing the English input and Hindi output. The parent has its own schema, and its translation node explicitly sends the English answer to the child and extracts the translated result.

Install the core packages

pip install -U langgraph langchain-openai

Set OPENAI_API_KEY in your environment before running the example. Model names may need to be changed to one available to your account.

Python

from typing import TypedDict
from langgraph.graph import StateGraph, START, END
from langchain_openai import ChatOpenAI

llm = ChatOpenAI(model="gpt-4o-mini", temperature=0)

# Child graph has its own, small state schema.
class TranslationState(TypedDict):
    input_text: str
    translated_text: str

def translate(state: TranslationState):
    response = llm.invoke(
        "Translate the text into natural, clear Hindi. "
        "Do not add explanations or extra content.\\n\\n"
        f"Text: {state['input_text']}"
    )
    return {"translated_text": response.content}

child_builder = StateGraph(TranslationState)
child_builder.add_node("translate", translate)
child_builder.add_edge(START, "translate")
child_builder.add_edge("translate", END)
translation_graph = child_builder.compile()

# Parent graph has a separate schema.
class ParentState(TypedDict):
    question: str
    english_answer: str
    hindi_answer: str

def generate_answer(state: ParentState):
    response = llm.invoke(
        f"Answer this question helpfully in English: {state['question']}"
    )
    return {"english_answer": response.content}

def translate_in_parent(state: ParentState):
    child_result = translation_graph.invoke(
        {"input_text": state["english_answer"], "translated_text": ""}
    )
    return {"hindi_answer": child_result["translated_text"]}

parent_builder = StateGraph(ParentState)
parent_builder.add_node("generate", generate_answer)
parent_builder.add_node("translate", translate_in_parent)
parent_builder.add_edge(START, "generate")
parent_builder.add_edge("generate", "translate")
parent_builder.add_edge("translate", END)
parent_graph = parent_builder.compile()

result = parent_graph.invoke({
    "question": "Why do plants need sunlight?",
    "english_answer": "",
    "hindi_answer": "",
})
print("English:", result["english_answer"])
print("Hindi:", result["hindi_answer"])
Follow the data: parent english_answer → child input_text → child translated_text → parent hindi_answer.

7. Example B — add the compiled subgraph as a parent node

Here, the child and parent share the same state shape. The parent graph can add the compiled child graph directly as a node, rather than writing a wrapper node that invokes it.

from typing import TypedDict
from langgraph.graph import StateGraph, START, END
from langchain_openai import ChatOpenAI

llm = ChatOpenAI(model="gpt-4o-mini", temperature=0)

class WorkflowState(TypedDict):
    question: str
    english_answer: str
    hindi_answer: str

def generate_answer(state: WorkflowState):
    response = llm.invoke(
        f"Answer this question helpfully in English: {state['question']}"
    )
    return {"english_answer": response.content}

def translate_shared_state(state: WorkflowState):
    response = llm.invoke(
        "Translate into natural, clear Hindi. Return only the translation.\\n\\n"
        f"{state['english_answer']}"
    )
    return {"hindi_answer": response.content}

# Child graph uses the same state schema as the parent.
child_builder = StateGraph(WorkflowState)
child_builder.add_node("translate", translate_shared_state)
child_builder.add_edge(START, "translate")
child_builder.add_edge("translate", END)
translation_graph = child_builder.compile()

# Add the compiled child graph directly as a parent node.
parent_builder = StateGraph(WorkflowState)
parent_builder.add_node("generate", generate_answer)
parent_builder.add_node("translate", translation_graph)
parent_builder.add_edge(START, "generate")
parent_builder.add_edge("generate", "translate")
parent_builder.add_edge("translate", END)
parent_graph = parent_builder.compile()

result = parent_graph.invoke({
    "question": "Why do plants need sunlight?",
    "english_answer": "",
    "hindi_answer": "",
})
print(result["english_answer"])
print(result["hindi_answer"])
Schema note: when a child graph is added directly, make sure its state schema and the parent’s state schema are compatible. A child graph can return updates for keys it owns; it does not need to overwrite every key.

8. Persistence, streaming, and observability

  • Persistence/checkpointing: LangGraph supports checkpointing for graph state. Configure a checkpointer on the parent graph and verify the behavior for your chosen LangGraph version and execution setup.
  • Streaming: graph execution can stream state updates or events. Subgraph-level streaming/visibility depends on the stream mode and configuration.
  • Inspecting subgraphs: compiled graph structures and execution traces can help investigate a focused component. Tracing products such as LangSmith can help examine calls, latency, and token usage when configured.
  • Retries and guardrails: implement retries, validation, timeouts, and fallback behavior intentionally; do not assume a subgraph automatically supplies these features.

The source lesson specifically recommends consulting the official LangGraph documentation for persistence, streaming, and viewing subgraph state. These details can evolve across releases.

9. Practical checklist

  • Give each subgraph one clear responsibility.
  • Choose between explicit invocation and adding the compiled graph as a node.
  • Decide whether parent and child state should be separate or shared.
  • Keep input/output keys explicit and document their meanings.
  • Test the child graph independently before integrating it.
  • Add error handling, retries, and fallbacks where needed.
  • Trace runs and inspect intermediate state when debugging.
  • Check official documentation for version-specific persistence and streaming options.

10. Quick glossary

GraphA workflow composed of connected steps.
NodeA step that performs work or invokes a component.
EdgeA connection defining what runs next.
Parent graphThe larger workflow that coordinates components.
SubgraphA compiled graph used as a component within a parent graph.
StateThe data passed through and updated by graph nodes.
CheckpointA saved snapshot of graph execution state, used for persistence and resuming workflows.
ObservabilityThe ability to inspect execution, intermediate results, errors, latency, and related signals.

One-minute revision

A subgraph lets you package a complex workflow into a reusable component. LangGraph commonly supports two integration patterns: call a child graph inside a parent node (useful for explicit mapping and separate state schemas), or add a compiled child graph directly as a node (useful when state schemas are compatible). Subgraphs improve modularity and can make reuse, maintenance, and tracing easier—but state design and error handling remain explicit engineering responsibilities.
